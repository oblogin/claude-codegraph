## Правила разработки кода

Проект — плагин Claude Code **claude-codegraph**: граф связей кода и память для агентов. Архитектура — `Docs/Tasks/Adr/` (главные: ADR-003 интерфейс, ADR-004 ядро на Rust, ADR-005 поставка, ADR-006 архитектура графа, ADR-007 хранение знаний).

- Ядро — Rust-воркспейс в корне репозитория, плагин — `plugin/`. Сборка: `cargo build --release`; перед закрытием задачи — `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, всё зелёное.
- Парсер разрабатывается от тестов: синтетические базы с ожидаемым графом — `Tests/fixtures/`, эталоны на реальных проектах — `Bench/`.
- Заимствованный чужой код (и код из `C:/ue-xray`) — только с записью в `THIRD_PARTY.md` (проект, файл, коммит, лицензия, куда взято).
- **Саморевью обязательно.** Прежде чем закрыть задачу с кодом, исполнитель:
  1. читает свой полный diff целиком, как чужой;
  2. проходит чек-лист: соответствие ADR и критериям задачи; крайние случаи и ошибки не проглатываются молча; нет `unwrap()` на данных извне; нет `INSERT OR REPLACE`; тесты покрывают каждый критерий; нет мёртвого кода и отладочного вывода; `THIRD_PARTY.md` обновлён;
  3. исправляет найденное и пишет в отчёте раздел «Саморевью» — что проверено и что исправлено; лид переносит это в журнал задачи.
- Для задач размера `L` и для хранилища, конвейера и разрешения связей — дополнительно независимое ревью отдельным агентом только для чтения по diff задачи; замечания исправляются до `done`.

## Конвейер работы (агенты и скиллы проекта в `.claude/`)

- Лид (основная сессия, Opus) исследует и планирует задачу скиллом `plan-task` (`.claude/skills/`) — план пишется в `### План реализации` раздела «Детали» задачи — и отдаёт её исполнителю скиллом `dispatch`.
- Агенты — `.claude/agents/`, только для этого проекта. Исполнители: `developer` (Sonnet) — по умолчанию; `senior-developer` (Opus) — только для самых сложных задач (разрешение связей C#, цепочки префабов Unity, инкрементальность, конкурентный доступ к базе); `tester` — тесты и прогоны; `researcher` — исследования по ТЗ; `reviewer` — независимое ревью (для ядра — с `model: opus`).
- Продолжение предыдущей задачи уходит тому же агенту, независимая задача — новому. Журналы и статусы задач ведёт только лид; исполнители не правят `Docs/Tasks/` и не коммитят.
- Ядро, для которого ревью обязательно: хранилище, конвейер индексации, разрешение связей, инкрементальное обновление.
