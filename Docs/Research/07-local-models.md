## Главное коротко

1. **OpenWhispr — не «маленькие модели для всего», а набор отдельных движков под каждую задачу.** Распознавание речи — whisper.cpp и sherpa-onnx (Parakeet, Nemotron, Cohere). Текстовые задачи (очистка диктовки, форматирование заметок, перевод, ассистент) — `llama-server` из llama.cpp с моделями GGUF. Поиск по смыслу — ONNX Runtime + all-MiniLM-L6-v2. Каждый движок — отдельный процесс, который запускается по требованию и выгружается после 5 минут простоя. [код]
2. **Их «простая задача» проще наших.** Очистка диктовки — это короткий текст на входе и почти такой же на выходе. Для неё они советуют модели от 230M до 1B параметров. Строго заданный формат ответа (JSON по схеме) OpenWhispr для локальной модели не использует. [код] Нашим задачам нужен структурированный вывод (тип, факты, файлы), поэтому нижняя граница у нас — модель на 2–4B.
3. **Локальную модель берём как необязательный модуль, по умолчанию выключенный.** Всё, что делает модель, у нас имеет запасной путь без модели (правило ADR-001 остаётся). Модель улучшает, но не заменяет.
4. **Отдаём модели:** классификацию наблюдений, сжатие журнала в конце сессии (в фоне), однострочные описания модулей (после MVP, лениво), разбор PDF по кускам с метками `INFERRED`/`AMBIGUOUS`. Поиск дублей по смыслу — отдельная модель эмбеддингов, только как подсказка.
5. **Не отдаём:** обобщение рецептов для глобальных знаний (это делает основной агент в текущей сессии по явной команде, человек подтверждает), фильтр секретов и приватности, рёбра графа кода, любую запись в git без подтверждения. Голосовые заметки не входят в плагин.
6. **Способ запуска — `llama-server` из llama.cpp: отдельный процесс на `127.0.0.1` с API, совместимым с OpenAI.** Плагин скачивает закреплённую сборку по команде пользователя (для Windows это 17 МБ версии для CPU, 39 МБ с Vulkan [проверено]). Вместо этого можно указать адрес уже установленных Ollama, LM Studio или своего `llama-server`. Решение не зависит от языка ядра (F03-02). Этот путь OpenWhispr проверил в работе под Windows.
7. **Модель по умолчанию — Qwen3.5-4B в квантовании Q4_K_M** (~2,7–3,0 ГБ, Apache-2.0, 201 язык, включая русский [проверено по карточке]). Лёгкий вариант — Qwen3.5-2B (1,4 ГБ), сильный — Qwen3.5-9B (5,9 ГБ). Запасная линейка — Gemma 4 E4B (Apache-2.0). Режим рассуждений (thinking) выключаем.
8. **Минимум железа** — x64 с AVX2, 16 ГБ ОЗУ, 4 ГБ на диске под модель 4B. С ним работают только фоновые задачи: сжатие сессии на CPU занимает минуты [оценка]. Для быстрых ответов нужна видеокарта с 6+ ГБ памяти и Vulkan (NVIDIA, AMD, Intel). На машине с 8 ГБ ОЗУ — только модель 2B и только классификация.
9. **Главное непроверенное — качество.** Хватит ли модели 4B на русских и английских журналах наших сессий, не проверял никто. Бенчмарки в карточках общие. Первая impl-задача должна начаться с набора из 30–50 реальных примеров и замера.

## 1. Как это устроено в OpenWhispr

### 1.1. Что это

Настольное приложение на Electron для диктовки: нажал горячую клавишу, сказал — текст появился под курсором. Есть заметки, запись встреч, голосовой ассистент. Лицензия — MIT [проверено: `LICENSE`]. Проект активный: последний коммит — 2026-09-29. Всё распознавание речи и все текстовые задачи могут работать локально или в облаке; по умолчанию после онбординга включено их собственное облако OpenWhispr Cloud [код: `docs/network-allowlist.md`].

### 1.4. Как скачивает и обновляет

- **Бинарники движков** закреплены по версии и приходят с обновлением самого приложения. Пакеты для видеокарт скачиваются по требованию в `userData/bin/<пакет>/`. Архив проверяется по sha256: для whisper CUDA сверка идёт с суммой, записанной в коде; иначе — с суммой, которую отдаёт GitHub API. Каждый пакет ставится в свою папку, потому что у пакетов одинаковые имена DLL и один перезаписал бы другой. Установка атомарная: пакет распаковывается рядом и подменяется одним переименованием [код: OW:src/helpers/gpuBinaryManager.js].
- **Модели** скачиваются по кнопке, по адресу `https://huggingface.co/{hfRepo}/resolve/main/{fileName}`. Загрузка сначала идёт во временный файл `.tmp`, умеет продолжать с места обрыва (заголовок `Range`) и делает до 3 повторов. Перед загрузкой проверяется свободное место: нужен размер модели плюс 20% [код: OW:src/helpers/downloadUtils.js, OW:src/helpers/modelManagerBridge.js].
- **Целостность модели не проверяется по хэшу.** Проверяется только, что файл больше минимального размера [код: `MIN_FILE_SIZE` в `modelManagerBridge.js`]. Это мы не повторяем: Hugging Face отдаёт sha256 каждого файла через API [проверено].
- **Список моделей** — JSON внутри приложения. Новые модели появляются только с новой версией приложения; сами модели не обновляются.
- Для некоторых моделей Gemma 4 рядом скачивается маленькая модель-«черновик» (MTP) для ускоренной генерации. Если она не скачалась, основная модель работает без неё [код].

### 1.5. Как работает под Windows (уроки)

Всё ниже — [код], с номерами задач в их трекере, где они указаны.

- **Лестница отката по видеокарте:** Vulkan с черновиком → Vulkan без черновика → Vulkan с урезанным контекстом → CPU. Проверить, хватит ли памяти видеокарты, приложение не может, поэтому просто пробует по порядку. Переход на CPU медленнее в 10–30 раз — это их собственная оценка в комментарии [OW:src/helpers/llamaServer.js].
- **Размер контекста считается от памяти машины.** Без ограничения контекст по умолчанию равен полному контексту модели (128K+), и его кэш не помещался в память: Mac на 16 ГБ зависал до паники ядра (#1203). Теперь окно считается от свойств модели. Бюджет — половина ОЗУ минус 2 ГБ, нижняя граница — 16384 токена [OW:src/helpers/llamaContextPolicy.js; вся логика — чистая арифметика, 210 строк].
- **Флаг `--cache-ram` нужно ограничивать.** Без него `llama-server` резервирует 8 ГБ ОЗУ под кэш запросов [комментарий в коде].
- **Режим рассуждений надо выключать явно.** Для Qwen передаётся `chat_template_kwargs: {enable_thinking: false}`. Иначе модель тратит весь лимит токенов на рассуждение. Есть сборки, которые кладут ответ в `reasoning_content` (#809) [код].
- **Путь к моделям — только ASCII.** Нативные бинарники падают на Windows, если в пути есть пробелы, кириллица или иероглифы. Поэтому для пользователей с профилем вроде `C:\Users\Иван` модели переносятся в `C:\ProgramData\OpenWhispr\cache` [OW:src/helpers/modelDirUtils.js]. **Для нашей русскоязычной аудитории это критично.**
- **Конфликт `onnxruntime.dll`.** В Windows 11 в System32 лежит старая `onnxruntime.dll`, и загрузчик иногда берёт её вместо своей. OpenWhispr переименовывает свою библиотеку в `ow-onnxrt.dll` и правит таблицы импорта в бинарниках (#2054) [OW:CLAUDE.md]. Это довод против ONNX-пути у нас.
- Процессы запускаются с `windowsHide`, чтобы не мелькало окно консоли. Системный `llama-server` ищется через `where.exe`. Раз в 5 с идёт проверка здоровья; после 3 неудач сервер считается упавшим. После 5 минут простоя сервер останавливается, чтобы освободить видеопамять [код].
- Параметры по умолчанию: 4 потока, `temperature` 0,7, `max_tokens` 512, тайм-аут запроса 5 минут, тайм-аут запуска 2 минуты [код].

### 1.6. Как выбирается «локально или облако»

- Текстовые задачи разбиты на области: очистка диктовки, ассистент, форматирование заметок, чат, перевод [OW:src/config/inferenceScopes.ts]. У каждой области свой режим: `local` (своя GGUF), облако OpenWhispr, свой ключ облачного провайдера или `lan`/self-hosted — любой сервер, совместимый с OpenAI. В комментариях прямо названы LM Studio, Ollama и vLLM [OW:src/services/ai/inferenceProviders/lan.ts, OW:src/config/constants.ts].
- Все локальные области делят **один** `llama-server`, и в нём загружена одна модель. Сервер останавливается, когда ни одной области его модель больше не нужна [OW:src/helpers/localServerPolicy.js].
- **Запасные пути.** Если очистка не удалась, вставляется исходный текст диктовки, а пользователь видит уведомление «Original dictation pasted without AI cleanup». Если локальный Whisper упал, текст уходит в OpenAI, но только при настройке `allowOpenAIFallback`, а она по умолчанию выключена. Поиск заметок идёт по цепочке «облако → локальные векторы → FTS5»; пока модель эмбеддингов не загружена, отвечает FTS5 [код]. То есть **без модели приложение деградирует мягко, а не ломается.** Это ровно наш принцип.

### 1.7. Что берём из OpenWhispr

| Что | Как |
|---|---|
| Модель — отдельный процесс `llama-server` на `127.0.0.1`, запуск по требованию, остановка после 5 минут простоя, проверка здоровья | идея (код — JS под Electron, если ядро будет на Node, то по образцу) |
| Лестница отката Vulkan → CPU | идея |
| Контекст по бюджету памяти (`llamaContextPolicy.js`, чистые функции) + ограничение `--cache-ram` | код (MIT, перенос логики) |
| Закреплённая версия бинарника + sha256 + атомарная установка в свою папку | идея |
| Модели в пути только из ASCII на Windows | правило |
| Выключать thinking явно; ответ брать из `content`, а не из `reasoning_content` | правило |
| Режим «свой сервер, совместимый с OpenAI» (Ollama, LM Studio) как альтернатива встроенному | идея |
| Мягкая деградация: нет модели или она упала → результат без модели и честная пометка | правило |

**Чего не повторяем:** вшивать бинарник в установку (мы плагин, скачиваем по команде); проверять модель только по размеру (у нас будет sha256); облако по умолчанию; модели меньше 1B для задач со структурированным ответом.

## 2. Наши задачи-кандидаты

Скорость ниже — **[оценка]** для модели 4B в Q4_K_M. Для CPU ноутбука (8 ядер, DDR5): генерация 10–15 токенов/с, чтение запроса 60–150 токенов/с. Для видеокарты с 6–8 ГБ через Vulkan или CUDA: генерация 60–90 токенов/с, чтение запроса 1500+ токенов/с. Откуда эти числа — в разделе 5. Холодный старт `llama-server` с моделью 3 ГБ — ещё 2–10 с.

|---|---|---|---|---|---|---|
| 1 | **Классификация наблюдения**: тип (`bugfix`, `decision`, `discovery`…), понятия (`gotcha`, `trade-off`…), метки технологий, «похоже на общий рецепт?» | ~300–800 токенов → 20–50 токенов JSON по перечню значений | **Да.** 2B справится с типом и метками, 4B надёжнее с понятиями. **Общие правила для всех задач модели.**
- Модель не вызывается в хуке синхронно. Хук только пишет событие (≤ 500 мс, ADR-001, раздел 4). Работа модели идёт через очередь: в фоне по `SessionEnd` или лениво при следующем запуске, короткоживущим процессом без демона.
- Ответ — только JSON по схеме: у `llama-server` это `response_format` / `json_schema`, внутри работает грамматика. Ответ проверяется; при ошибке делаем один повтор, затем результат без модели.
- Всё, что сделала модель, помечено: `source: model`, имя и версия модели, дата. Это недоверенный текст (ADR-001, раздел 5). В git такой текст попадает только явным действием.
- Вывод модели никогда не превращается в действие: не вызывает инструменты и не меняет граф кода. Защищает от промпт-инъекций из вывода инструментов.
- Фильтр приватности применяется **до** отправки текста модели, хотя модель и локальная: так в её кэш и в логи сервера не попадают секреты.

Язык ядра (F03-02) на этот выбор не влияет: из ядра нужен только HTTP-клиент и запуск процесса.

**Оговорка про релизы llama.cpp.** Последний релиз `ggml-org/llama.cpp` на 2026-09-29 — `v0.5.0` от 2026-09-23. В нём один файл, `nightly-tag.txt`, без бинарников [проверено]. ## 5. Скорость и железо

### 5.1. Откуда оценки скорости

- **Генерация ограничена пропускной способностью памяти.** Каждый токен читает весь файл модели. Для модели 3 ГБ на ноутбучной DDR5 (реально 40–60 ГБ/с) выходит ~13–20 токенов/с в лучшем случае, на практике около 10–15 [оценка]. Для видеокарты с GDDR6 (250–450 ГБ/с) — 60–100+ [оценка].
- Сторонние замеры согласуются с оценкой. На CPU модели 3–7B в Q4_K_M дают 4–15 токенов/с. Phi-4-mini на CPU — ~12 токенов/с, Llama 3.2 3B — ~10. Qwen3 8B Q4_K_M на настольном Ryzen 9 7950X: чтение запроса 210 токенов/с, генерация 26 токенов/с [заявлено: promptquorum.com и сводка llama-bench; ссылки в конце].
- **Чтение запроса** на CPU упирается в вычисления: для 4B это 60–150 токенов/с на 8 ядрах [оценка]. Поэтому длинный вход (выжимка сессии, кусок PDF) на CPU стоит десятки секунд — только фоном.
- Своих замеров нет. У пользователя настольный Ryzen 7 5800X, 128 ГБ ОЗУ и RTX 4090 [проверено на машине]. Для команды и сообщества это не типичный ноутбук. Замер на 2–3 ноутбуках команды — в impl-задаче.

### 5.2. Уровни железа

| Уровень | Железо | Модель | Что работает | Скорость [оценка] |
|---|---|---|---|---|
| 0 — без модели | любое | — | **Всё.** Каждая функция идёт своим путём без модели | — |
| 1 — минимальный | x64 с AVX2, 8 ГБ ОЗУ (свободно ≥ 3 ГБ), 2 ГБ диска | Qwen3.5-2B Q4_K_M (1,4 ГБ) | Только классификация (задача 1) | 2–5 с на наблюдение |
| 2 — **рекомендуемый минимум** | x64 с AVX2, **16 ГБ ОЗУ**, 4 ГБ диска; видеокарта необязательна | Qwen3.5-4B Q4_K_M (~3 ГБ + 0,5–1,5 ГБ на контекст 8–16K) | Классификация; сжатие сессии в фоне; описания модулей и PDF — медленно, ночью или по команде | Сжатие сессии — 1–5 мин |
| 3 — комфортный | Видеокарта с ≥ 6 ГБ памяти и Vulkan (NVIDIA, AMD, Intel Arc) или CUDA | Qwen3.5-4B, или 9B при ≥ 8 ГБ видеопамяти | Всё из списка «отдаём», почти мгновенно | Сжатие сессии — 10–30 с |

**Особенность команды — Unity.** Редактор Unity сам занимает много ОЗУ и видеопамяти. Поэтому модель работает с пониженным приоритетом процесса, число потоков — половина ядер, и после 5 минут простоя модель выгружается. Если видеопамяти не хватило, срабатывает лестница Vulkan → CPU по образцу OpenWhispr.

## 6. Что обязательно, а что по желанию

| Обязательно | По желанию |
|---|---|
| Все функции работают без модели: детерминированное сжатие, классификация правилами, L0/L1 без модели, PDF — текст и имена, поиск — FTS5/BM25 | Локальная модель (источник А или Б), по умолчанию выключена |
| Честная пометка в ответах, чем сделан результат: `source: rules` или `source: model` | Эмбеддинги для поиска дублей — только после замера на F-02 |
| Фильтр приватности до любой обработки | Описания модулей и смысловой проход по PDF моделью |
| Никаких облачных моделей и второго процесса Claude для этих задач | Внешний сервер не на `localhost` — только явной настройкой с предупреждением |

Включение — одной командой плагина (например, `/<плагин>:local-model setup`). Она показывает размер загрузки и требования, проверяет свободное место, скачивает бинарник и модель со сверкой sha256 и пробно отвечает на один запрос. Выключение — командой или удалением папки.

## 7. Что проверить в impl-задаче

1. **Набор примеров.** 30–50 реальных фрагментов журнала на русском и английском, для каждого — эталон (тип, понятия, выжимка). Модели Qwen3.5-2B, Qwen3.5-4B, Gemma 4 E4B против правил без модели. Метрики: точность типа и понятий, доля выдуманных фактов (проверяет человек), доля ответов с валидным JSON.
2. **Скорость** на 2–3 ноутбуках команды: только CPU и с Vulkan. Замеры: чтение запроса, генерация, холодный старт; всё это при открытом редакторе Unity.
3. **Откуда брать сборки llama.cpp** после смены схемы релизов (`v0.5.0` без бинарников).
4. **Фоновая работа без демона на Windows.** Отсоединённый процесс по `SessionEnd`: без мелькания консоли, переживает закрытие Claude Code, не запускает второй экземпляр.
5. **JSON по схеме в `llama-server` с Qwen3.5 при выключенном рассуждении**: ответ приходит в `content`, а не в `reasoning_content` (урок #809 OpenWhispr).
6. **Путь с кириллицей** в профиле пользователя: плагин переносит модели в путь из ASCII.
