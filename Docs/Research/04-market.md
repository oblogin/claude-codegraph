## Главное коротко

1. **Карта кода в 2026 году стала обычным делом.** С августа 2025 по март 2026 появились как минимум четыре крупных открытых проекта с одним набором приёмов: tree-sitter → граф в SQLite → MCP-инструменты «кто вызывает» и «что заденет правка» → хуки для обновления графа. Это `colbymchenry/codegraph`, `codebase-memory-mcp`, `GitNexus` и `code-review-graph`. Если делать то же самое, мы не выделимся. Выделиться можно только тем, чего у них нет.
2. **Unity никто не поддерживает.** Все четыре лидера разбирают C# как обычный C#. Сцены, префабы, связи через GUID в `.meta`, методы вроде `Update`/`Start`, которые вызывает движок, `[SerializeField]`, `UnityEvent` они не видят. В трёх клонах я поискал `MonoBehaviour` в исходниках и ни одного упоминания не нашёл (код). Unity-MCP-серверы управляют редактором, а не строят граф. Единственное исключение — однозвёздный `verysleepylemon/unity-mcp`: он выгружает граф сцен из редактора.
3. **Точность разбора связей — главное слабое место у всех.** Лучше всех здесь `codebase-memory-mcp`: у него свой встроенный слой вывода типов (C#, Go, Rust, TS и др.), без запуска языковых серверов. Serena использует настоящие языковые серверы (Roslyn для C#, gopls, rust-analyzer) и поэтому точна, но работает медленно, и графа у неё нет.
4. **Честные цифры тоже есть, и они отрезвляют.** В статье о `codebase-memory-mcp` (arXiv 2603.27277, заявлено) агент с графом отвечает правильно в 83% случаев. Агент, который просто читает файлы, — в 92%, зато тратит в 10 раз больше токенов. `codegraph` сам признаёт, что к концу сессии его ответы занимают в контексте примерно на 80% больше места. Вывод: граф экономит токены, но не обязательно улучшает ответы. Наш набор проверок (F-02) должен мерить качество, а не только токены.
5. **Память команды в git — рабочая идея, и её уже по-разному реализуют.** Beads (от JSONL в git перешли к Dolt), ai-memory (Markdown-вики в git как источник правды, SQLite как производный индекс), Letta Context Repositories (память — это git-репозиторий файлов). `codebase-memory-mcp` предлагает коммитить сам граф одним сжатым файлом. Авторы честно предупреждают, что так история репозитория разрослась у одной команды до 6 ГБ.
6. **Для ядра есть хорошие готовые компоненты:** tree-sitter (официальные привязки для Rust, Go, Node/WASM), SQLite + FTS5, Tantivy, индексаторы SCIP (scip-dotnet, scip-go, rust-analyzer, scip-typescript), локальные модели эмбеддингов для кода с лицензиями MIT/Apache (CodeRankEmbed, jina-v2-base-code). От двух вещей надо отказаться: `github/stack-graphs` в архиве с 2025-09-09, а Kuzu в архиве с октября 2025 (его продолжает форк LadybugDB).

## 2. Подробные разборы (8 решений)

### 2.1. colbymchenry/codegraph

**Что это.** Локальный граф кода для Claude Code, Cursor, Codex и других агентов. CLI `codegraph` плюс MCP-сервер. Появился в январе 2026. MIT. Авторы готовят платный облачный продукт `getcodegraph.com` (заявлено).

**Как устроено (код).**
- Разбор: ядро на Rust с вкомпилированными грамматиками tree-sitter для 20 языков (`codegraph-kernel/src/*.rs`, для C# — `codegraph-kernel/src/csharp.rs`, 1 626 строк). Для остальных языков и файлов с ошибками есть запасной путь на `web-tree-sitter` (WASM) (`package.json`: `web-tree-sitter`, `tree-sitter-wasms`).
- Хранение: SQLite через встроенный в Node `node:sqlite` (`src/db/sqlite-adapter.ts`), схема — в `src/db/schema.sql`: таблицы `nodes`, `edges`, `files` (хэш содержимого, флаг «сгенерированный файл»), `unresolved_refs`, полнотекстовый поиск FTS5 `nodes_fts`.
- **У каждой связи записан источник** — `edges.provenance`: `'tree-sitter' | 'scip' | 'heuristic'` (`src/types.ts:227`).
- **Неразрешённые ссылки не выбрасываются.** Они лежат в `unresolved_refs` со статусом `pending/failed`. При следующей синхронизации ссылка разрешается заново, если появился подходящий символ (комментарий в `src/db/schema.sql`).
- Разрешение вызовов идёт по эвристикам с учётом языка: `src/resolution/name-matcher.ts` (4 427 строк), отдельные «синтезаторы» для роутеров и фреймворков (`src/resolution/*-synthesizer.ts`).
- Свежесть графа: слежение за файлами с паузой 2 с (`src/sync/watcher.ts`). Git-хуки `post-commit/post-merge/post-checkout` вписываются между маркерами, так что их можно безопасно добавить и убрать (`src/sync/git-hooks.ts`). Перед ответом **файлы, из которых собран ответ, заново хэшируются**, и устаревшие помечаются (`src/mcp/answer-freshness.ts`, `validateAnswerFiles`).
- MCP: **по умолчанию виден один инструмент** `codegraph_explore` (`src/mcp/tools.ts:1850`, `DEFAULT_MCP_TOOLS = new Set(['explore'])`). Остальные (`callers`, `impact` и т. п.) включаются переменной окружения. Инструкции для агента передаются в ответе MCP `initialize` (`src/mcp/server-instructions.ts`), а не записываются в CLAUDE.md.
- CLI `codegraph affected` находит тестовые файлы, которые затрагивают изменённые файлы: транзитивно по импортам, глубина 5 (README).

**Что полезно нашим слоям.**
- Карта: одна «толстая» команда вместо меню узких инструментов. Авторы пишут, что так агент реже ошибается с выбором (заявлено). Пометка источника на каждой связи. Таблица неразрешённых ссылок с повторной попыткой.
- Последствия правок: `affected` (правка → тесты) и раздел «радиус поражения» в ответе `explore`.
- Проверка: `codegraph affected --stdin` в хуке или CI запускает только затронутые тесты.
- Методика: они меряют «покрытие межфайловых связей» для каждого языка, например C# 85,2% на MediatR, Go 96,6% на gin, Rust 86,7% на ripgrep (заявлено). Метрика слабая: она считает только, есть ли у файла хоть одна входящая связь, точность не проверяет. Но сама идея — мерить на эталонных репозиториях — подходит для F-02.

### 2.3. GitNexus (abhigyanpatwari/GitNexus)

**Можно ли взять код.** MIT, Go, но всё сильно завязано на Dolt. Брать идеи.

**Слабые места.** Dolt — тяжёлая зависимость. Код с множеством ролей и огромными комментариями сложен для чтения. Это трекер задач, а не знания о коде.

**Вердикт: взять идею** — хэш-ID, `supersedes/duplicates`, `prime`, разделение «общее/локальное», stealth-режим. Отдельно зафиксировать урок «JSONL → Dolt».

### 2.8. ai-memory (akitaonrails/ai-memory)

**Что это.** Долгая память для 20+ coding-агентов с передачей работы между ними. Один бинарник на Rust, MCP/HTTP-сервер. MIT. Появился в мае 2026. Нативный Windows — «Experimental», через WSL2 поддерживается (README).

**Как устроено (README и `docs/ARCHITECTURE.md`).**
- **Источник правды — Markdown-вики в git** (`<data_dir>/wiki/`, репозиторий через `git2`): каждое сведение сессии — коммит. `db/memory.sqlite` — **производный индекс**, его всегда можно пересобрать. Правки вручную (Obsidian, vim) подхватываются.
- Хуки записывают наблюдения. Приватные данные вычищаются на типизированной границе до записи. В конце сессии наблюдения собираются в страницы вики. Путь по умолчанию работает **без единого вызова LLM**.
- Поиск: FTS5 + сущности + соседи по графу ссылок + (по желанию) векторы, всё сводится через RRF.
- Уровни памяти (раздел Storage architecture): Working, Episodic, Semantic и Procedural со своими сроками. Формула забывания учитывает важность, время, число обращений и число разных людей, которые обращались. **Сжатие вместо удаления**: у холодной страницы остаются пути, коды ошибок и решения, полный текст — в git.
- `page_evidence` хранит, какие сессии подтвердили страницу. Из этого выводится «уверенность» от 0 до 0,95: сколько разных сессий, насколько свежие, сколько противоречий. `page_feedback` (`helpful/not_helpful/stale/wrong`) — сигналы полезности.
- Передача работы (handoff) типизирована: «принята ровно один раз».
- Команда: общий сервер, у каждой записи есть автор, аудит. Это **не** git в репозитории проекта: вики живёт в каталоге данных сервера.
- В `docs/comparison.md` и `docs/competitive-parity.md` авторы сами сравнивают себя с agentmemory, mcp-memory-service и др. Полезно для F01-02.

**Что полезно нашим слоям.** Журнал работы и знания проекта — почти готовая модель: Markdown в git как правда, SQLite как индекс, уровни памяти, забывание по формуле, «уверенность» по числу подтверждений, отзывы о полезности, вычистка приватного при записи, работа без LLM по умолчанию.

**Можно ли взять код.** MIT, Rust, разбит на крейты (`crates/ai-memory-store`, `ai-memory-wiki`, `ai-memory-consolidate`, `ai-memory-hooks`…). Отдельные крейты взять можно, если ядро будет на Rust. Иначе — идеи.

**Слабые места.** Для команды нужен общий сервер. Наша цель — общие знания прямо в git репозитория, так что модель придётся адаптировать. Нативный Windows экспериментальный. Проекту 4 месяца, он очень большой.

**Вердикт: взять идею** — главная модель для F-06 и F-07. Для F01-02 и F01-06 — сравнить с agentmemory и claude-mem.

## 3. Короткие заметки о других важных решениях

### 3.1. Graphiti (Zep)
Граф знаний, в котором у каждой связи есть время: `valid_at`, `invalid_at`, `expired_at` (`graphiti_core/edges.py:271–277`, код). Новый факт не стирает старый, а закрывает его срок действия (`graphiti_core/utils/maintenance/edge_operations.py`, код). Каждый факт ссылается на эпизод-источник. Минусы: на каждый эпизод нужен вызов LLM для извлечения, нужна графовая база (Neo4j, FalkorDB, Kuzu, Neptune). **Вердикт: взять идею** — для знаний проекта хранить «когда стало верно / когда перестало» и ссылку на источник вместо перезаписи.

### 3.2. Letta Context Repositories
Память агента — git-репозиторий файлов. Дерево файлов всегда лежит в системном промпте, у файлов есть описание во frontmatter, каталог `system/` загружается всегда. Субагенты пишут память каждый в своём worktree, потом изменения сливаются (заявлено, блог Letta). **Вердикт: взять идею** — постепенное раскрытие через дерево файлов и описания во frontmatter; параллельная запись через worktree.

### 3.3. claude-context (Zilliz) и индексация Cursor
Оба используют **дерево Меркла по хэшам файлов**, чтобы пересчитывать только изменённое, и разбивку на куски по синтаксису. Cursor ещё кэширует эмбеддинги по содержимому куска и по simhash находит готовый индекс коллеги (заявлено). claude-context требует Milvus или Zilliz Cloud. **Вердикт: взять идею** — кэш по хэшу содержимого куска; простой обмен индексом внутри команды.

### 3.4. Continue
Отказался от `@codebase` (RAG, который сам подмешивает контекст) в пользу инструментов агента. Были проблемы с нативным модулем LanceDB (AVX2/FMA). **Вывод:** агенты лучше пользуются инструментами, которые вызывают сами, чем подмешанным контекстом; нативные векторные базы — риск для переносимости.

### 3.5. CodeRabbit, Augment, Sourcegraph
Закрыты. Из открытого после Sourcegraph остался **SCIP**. Приёмы CodeRabbit (граф на каждое ревью, контекст «намерение + код + стандарты») — ориентир для F-09.

### 3.6. Unity-MCP-серверы
`mcp-unity` и `Unity-MCP` управляют редактором, а не строят граф. `verysleepylemon/unity-mcp` — единственный найденный граф «сцена → GameObject → компонент → ссылки из инспектора + вызовы `Instantiate()`», но он выгружает данные **из редактора** и имеет 1 звезду (заявлено). **Вердикт для F-10:** взять идею трёх слоёв (граф кода, граф сцен, граф порождения объектов). Нужно решить, разбирать ли YAML `.unity`/`.prefab`/`.meta` без редактора (не нужен запущенный Unity) или выгружать из редактора (точнее, но нужен Unity).

## 7. Что это значит для следующих задач

- **F01-06 (что берём):** основной список — таблица §6. Код реально можно взять из: SolidLSP (MIT), маленьких модулей code-review-graph (MIT), формулы Aider (Apache-2.0), отдельных проходов CBM (MIT) как алгоритмов. **GitNexus — только идеи** (некоммерческая лицензия). **Serena-приложение и basic-memory — не брать код** (GPL/AGPL).
- **F03-01 (своё ядро или готовый движок):** есть два реальных кандидата в «готовые движки» — `codebase-memory-mcp` (MIT, один бинарник, Windows) и `colbymchenry/codegraph` (MIT, есть библиотечный API). У обоих нет Unity, и расширять их — это писать на C или разбираться в огромном TypeScript-резолвере. Предлагаю прогнать оба на наборе F-02 и сравнить качество (не только токены) с простым «агент читает файлы».
- **F03-03 (хранение):** SQLite + FTS5 — консенсус. Для общей памяти команды — урок Beads (JSONL в git → Dolt) и урок CBM (бинарный граф в git раздувает историю). Разумный путь — «Markdown в git как правда, SQLite как локальный индекс», как в ai-memory, Serena и Letta.
- **F03-04 (интерфейс):** один главный инструмент, урезанные профили для субагентов, инструкции через `initialize`, пометки о неуверенности.
- **F-10 (Unity):** ниша свободна. Решить, разбирать ли YAML сцен и префабов без редактора или выгружать граф из редактора.
- **F-02 (набор проверок):** мерить качество ответов, а не только токены. Хороший пример честности — «Limitations» в code-review-graph и цифры 83% против 92% в статье CBM.
