# F02-03 Тестовые кодовые базы с ожидаемым графом

> **Что:** написать маленькие кодовые базы на каждом языке стека, для которых заранее известен правильный граф связей, и автотесты «разбор базы → граф совпадает с ожидаемым».
> **Зачем:** парсер разрабатывается от тестов: каждая особенность языка (наследование, интерфейсы, события, вложенные префабы…) проверяется отдельно и не ломается при следующих правках.
> **Готово, когда:** в `Tests/fixtures/` есть базы для C#, Unity-ассетов, TS, Go и Rust с файлами ожидаемого графа, а тест-раннер сравнивает с ними вывод любого индексатора и печатает недостающие и лишние связи.

## Критерии готовности

- [x] C#: наследование и переопределение, интерфейсы и явная реализация, перегрузки, дженерики, события и делегаты, лямбды, `partial`, расширения, одноимённые методы в разных классах (ловушки), `using`-алиасы, asmdef-сборки
- [x] Unity-ассеты: `.meta` с GUID, сцена с объектами и скриптами, префаб, вложенный префаб, вариант префаба с удалённым и добавленным компонентом, UnityEvent → метод, сообщения движка, `SerializeField`, Addressables-ссылка, строковый `Resources.Load` (литерал и нелитерал)
- [x] TS/JS: классы и наследование, интерфейсы, модули ES и реэкспорты, алиасы `tsconfig` `paths`, динамический `import()`, колбэки и события, одноимённые функции в разных модулях
- [x] Go: пакеты, методы с получателем, интерфейсы с неявной реализацией, встраивание структур, горутины и каналы с функциями, одноимённые методы разных типов
- [x] Rust: модули и `use`, трейты и `impl`, дженерики с ограничениями, `impl Trait`, `dyn Trait`, макросы (отметить, что ожидаем), одноимённые методы разных типов
- [x] Для каждой базы — файл ожидаемого графа в формате `Bench/README.md` (тот же формат, что у эталонов F02-01), с пометкой, какие связи обязательны, какие допустимо пропустить (например, `dyn Trait`), а какие не должны появиться (ловушки)
- [ ] ~~Тест-раннер~~ → перенесено в [[F02-02 Скрипт прогона набора проверок]] (крейт Rust по ADR-004)
- [ ] ~~Прогон базовой линии grep~~ → перенесено в [[F02-02 Скрипт прогона набора проверок]]

## Детали

Предложение пользователя 2026-09-29, принято лидом: «знаем, что такая кодовая база должна выдавать такой граф — пишем базу, прогоняем, пишем тест». Дополняет эталоны на реальных открытых проектах ([[F02-01 Эталонные связи в наших проектах]]): синтетические базы проверяют каждую особенность языка точно, реальные — масштаб и неожиданные случаи.

Базы маленькие (10–40 файлов), код компилируемый по смыслу, но собирать и запускать его не нужно. Unity-сцены и префабы пишутся вручную в текстовом YAML по образцам из отчёта `Docs/Research/05-unity-and-web-engines.md`.

## Проверка

1. Запустить тест-раннер с адаптером grep: он проходит по всем базам и печатает отчёт с полнотой и точностью.
