# F02-01 Эталонные связи в наших проектах

> **Что:** выбрать 2–4 наших проекта и выписать 10–20 известных связей и несколько типовых задач с ожидаемым результатом.
> **Зачем:** это эталон, по которому меряем карту кода и последствия правок.
> **Готово, когда:** в `Bench/cases/` лежат описания эталонов, по каждому языку стека есть хотя бы две связи.

## Критерии готовности

- [x] Выбраны проекты: Unity (C#), браузерная игра (JS/TS), сервер на Go, по возможности расширение на Rust
- [x] По каждому проекту — связи «символ → все его потребители», включая непрямые вызовы, события, связи скрипт ↔ префаб в Unity
- [x] Несколько задач «изменить X — что должно быть затронуто»
- [x] Формат эталона описан и одинаков для всех проектов

## Детали

Решение лида (2026-09-29): не ждать проектов пользователя. Первая версия набора — на открытых проектах, похожих на наш стек, плюс наш код:
- Unity — открытый проект с текстовыми сценами и префабами (например, Unity Open Project «Chop Chop», уже разобранный в F01-05);
- JS/TS — открытая браузерная игра на своём движке или небольшой движок на TS;
- Go — открытый игровой или сетевой сервер среднего размера;
- Rust — открытый проект среднего размера (не `C:/ue-xray`: это система графа и парсинга Unreal, а не представитель наших Rust-проектов).
Эталоны составляет агент по коду вручную (чтением, без графа), с пометкой источника каждой связи. Проекты пользователя добавим, когда он их пришлёт.

## Проверка

1. Открыть `Bench/cases/`: у каждого эталона указаны проект, символ, ожидаемые потребители.
