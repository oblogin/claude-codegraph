# F01-06 Что берём из разобранных решений

> **Что:** свести пять отчётов и выбрать приёмы и готовый код для каждого слоя системы.
> **Зачем:** архитектурные задачи опираются на один согласованный список, а не на разрозненные отчёты.
> **Готово, когда:** есть ADR со списком «слой → приём → откуда → берём код или идею» и списком отвергнутого.

## Критерии готовности

- [x] Для каждого слоя (карта, последствия, Unity, журнал работы, знания проекта, документы, проверка) выбраны приёмы с источником
- [x] Для каждого кандидата на готовый код указано, что именно и почему
- [x] Отвергнутые приёмы перечислены с причиной
- [x] Решение записано в ADR (`Adr/`), impl-задача может стартовать без повторного исследования

## Детали

Вход — отчёты в `Docs/Research/01…05`. Принцип отбора: только то, что закрывает четыре проблемы пользователя (изучение с нуля, сломанные зависимости, забытые решения, проверка), и минимум инструментов MCP.

## Проверка

1. ADR отвечает на все вопросы из критериев; зависимую impl-задачу можно делать, не возвращаясь к исследованию.
