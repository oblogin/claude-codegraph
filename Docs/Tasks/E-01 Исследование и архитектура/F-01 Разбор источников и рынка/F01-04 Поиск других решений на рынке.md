# F01-04 Поиск других решений на рынке

> **Что:** найти и кратко разобрать решения для контекста, карты кода и памяти coding-агентов, кроме девяти уже известных.
> **Зачем:** не пропустить лучший готовый приём или движок.
> **Готово, когда:** в `Docs/Research/04-market.md` есть таблица найденных решений и подробный разбор 5–8 самых интересных.

## Критерии готовности

- [x] Найдено не меньше 15 решений с короткой характеристикой (категория, открыт ли код, лицензия, язык, активность)
- [x] 5–8 самых полезных для нас разобраны по структуре отчёта
- [x] Отмечены решения с хорошей поддержкой C#, Unity, Go, Rust
- [x] Отчёт лежит в `Docs/Research/04-market.md`

## Детали

Уже разбираются в других задачах, не повторять: Greptile, Graft, Graphify, CodeGraph, agentmemory, claude-mem, OpenViking, оба Ouroboros.

С чего начать поиск: Serena (LSP-инструменты для агентов), Aider repo-map, Sourcegraph / Cody, CodeRabbit, Continue, индексация Cursor, Zep / Graphiti, Mem0, Letta, code-graph MCP-серверы, SCIP / LSIF, stack-graphs от GitHub, tree-sitter-graph, новые проекты 2026 года.

Отдельно — готовые компоненты, которые можно взять в ядро: библиотеки разбора (tree-sitter и привязки), индексаторы SCIP, встраиваемые хранилища и поиск (SQLite FTS5, LanceDB, Tantivy и т. п.), локальные модели эмбеддингов.

Структура отчёта для каждого решения: что это и для чего; как устроено на самом деле (со ссылками на файлы в исходниках, если они открыты); механизмы, полезные для наших слоёв (карта, последствия правок, журнал работы, знания проекта, документы, проверка); можно ли взять код (лицензия, язык, насколько отделяется); слабые места; вердикт — «взять код», «взять идею» или «не брать». В конце — сводная таблица приёмов.
