# F03-06 Архитектура графа и конвейер индексации

> **Что:** спроектировать модель графа (узлы, рёбра, идентичность, метки), конвейер индексации, хранение, инкрементальное обновление, слой запросов и модули языков.
> **Зачем:** граф — ядро системы; от его архитектуры зависят точность, скорость, расширяемость и всё, что строится сверху (последствия правок, Unity, память, документы).
> **Готово, когда:** есть ADR с моделью графа, схемой хранения, конвейером и интерфейсом модуля языка, по которому можно писать код и тесты F02-03 без повторного проектирования.

## Критерии готовности

- [x] Модель графа: виды узлов (файл, модуль, тип, метод, поле, ассет, объект сцены, документ, раздел, запись памяти…) и рёбер (вызов, наследование, реализация, импорт, ссылка, скрипт-на-объекте, UnityEvent, упоминание в документе…), слои (код, ассеты, документы, память) в одном пространстве идентификаторов
- [x] Идентичность узла: стабильный ключ символа, не зависящий от переиндексации (по образцу SCIP), хэш тела для устаревания
- [x] Метки рёбер: источник (tree-sitter, LSP, эвристика, модель), уверенность, доказательство (файл и строка); неразрешённые ссылки с кандидатами
- [x] Конвейер: поиск файлов (учёт `.gitignore`) → извлечение фактов из файла (параллельно, кэш по хэшу содержимого) → разрешение связей между файлами → необязательное уточнение через языковой сервер → запись
- [x] Инкрементальность: что пересчитывается при изменении одного файла; целевые времена (холодная индексация и обновление)
- [x] Хранение: схема SQLite (таблицы, индексы, FTS), запросы по графу (рекурсивные CTE или кэш смежности в памяти), размер базы
- [x] Слой запросов: небольшой набор запросов, на которые опираются инструменты MCP из [[F03-04 Интерфейс для агента]]
- [x] Интерфейс модуля языка и формата (C#, TS, Go, Rust, Unity-YAML, Markdown): что он получает и что отдаёт; как модуль тестируется на базах [[F02-03 Тестовые кодовые базы с ожидаемым графом]]
- [x] Решение «своё ядро или готовое» ([[F03-01 Своё ядро или готовый движок]]) и язык ядра ([[F03-02 Язык ядра и способ поставки]]) принимаются вместе с этой архитектурой
- [x] Решение записано в ADR (`Adr/`), impl-задача может стартовать без повторного исследования
