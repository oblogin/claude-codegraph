# F03-05 Форматы хранения знаний и их жизнь

> **Что:** сравнить, как готовые системы хранят знания и справляются с их ростом, устареванием, дополнением и правкой, и подготовить варианты для обсуждения с пользователем.
> **Зачем:** Markdown-файл на запись может превратиться в свалку при десятках тысяч записей; формат нужно выбрать до реализации памяти.
> **Готово, когда:** в `Docs/Research/09-knowledge-storage.md` есть сравнение подходов и 2–3 варианта для нашей системы с плюсами и минусами, готовые к обсуждению.

## Критерии готовности

- [x] Разобрано по исходникам, как хранят знания и как они живут: ai-memory, Letta (context repositories, memory blocks), Graphiti/Zep, basic-memory, Beads (переход с JSONL на Dolt), OpenViking, Serena memories, Mem0 — и что найдётся ещё
- [x] По каждому: единица хранения (факт, запись, страница, узел графа), масштаб, как устаревает (версии, затухание, пометки), как дополняется и правится, как сливается у нескольких людей, как человек это читает
- [x] Оценены подходы: файл на запись, страница на тему с фактами внутри, SQLite, база + текстовая выгрузка, версионируемая БД (Dolt и др.), граф знаний с временем (bi-temporal)
- [x] Учтены наши требования: знания проекта в git проекта; личная глобальная база с подключением и слиянием чужих баз ([[F-14 Глобальная база знаний]]); привязка к символам кода и пометка устаревшего; журнал работы отдельно и локально
- [x] Предложены 2–3 варианта для нашей системы с плюсами и минусами и рекомендацией
- [x] Отчёт лежит в `Docs/Research/09-knowledge-storage.md`
