# E-01 Исследование и архитектура

> **Что:** разобрать готовые решения для контекста и памяти coding-агентов, собрать набор проверок на наших проектах и принять архитектурные решения.
> **Зачем:** строим своё не с нуля, а из проверенных приёмов, и можем измерить, что стало лучше.
> **Готово, когда:** есть ADR по выбору приёмов, ядру, хранению и интерфейсу для агента, а набор проверок запускается на наших проектах.

## Цель

**claude-codegraph** — плагин Claude Code, который даёт агентам понимание наших проектов:

1. **Карта кода** — агент не изучает проект с нуля в каждой сессии: сжатая картина модулей и связей, подробности по запросу (L0 суть → L1 API → L2 исходник).
2. **Последствия правок** — перед правкой агент видит, кто зависит от кода и какие тесты его проверяют; после правки — что ещё может быть затронуто.
3. **Память** — личный журнал работы (автоматически, локально), знания проекта (в git проекта, Markdown) и глобальные знания команды — проверенные рецепты для всех проектов (отдельный git-репозиторий).
4. **Проверка изменений** — после MVP.

Стек наших продуктов: браузерные игры (JS/TS) на самописном движке без редакторов сцен, Unity последней версии (C#, сцены и префабы), серверы на Go, расширения на Rust. Unreal — после MVP. Документация: Markdown (README) и PDF.

Сначала делаем для своих продуктов, но архитектура — для сообщества: языки и форматы подключаются модулями, под наш стек ничего не зашивается.

Ограничения:
- не пишем своего агента и не делаем оркестрацию процесса (интервью, спецификации) — это Claude Code и `claude-tasks`;
- не тащим «всё лучшее отовсюду»: мало инструментов MCP, берём только то, что закрывает наши проблемы;
- код не уходит в чужие облака, кроме запросов к самой модели.
