# ADR-003 Интерфейс для агента

> **Решение:** агент получает шесть инструментов MCP: входной `explore`, затем `inspect`, `refs`, `impact` для кода и Unity и `recall`, `remember` для памяти; к ним — текст `instructions` в ответе `initialize`, пять хуков, которые только добавляют короткие факты и ничего не решают, девять команд плагина без расхода контекста и один лёгкий скилл. Всё это обслуживает один бинарник `codegraph`.
> **Почему:** так постоянный расход контекста — около 1,2 тыс. токенов на сессию, а подсказки приходят в тот момент, когда агент может ошибиться: при поиске по имени, при чтении сцены или префаба, сразу после правки; всё остальное агент запрашивает сам.
> **Следствия:** первая impl-задача каркаса плагина в [[F-04 Карта кода]] делает `codegraph mcp`, `codegraph hook <событие>` и `plugin/hooks/hooks.json` по этому контракту. Подмешивание контекста к каждому запросу, хук чтения кода и окончательное число инструментов решаются по замерам [[F02-02 Скрипт прогона набора проверок]].

## Контекст

**Что решаем.** Нужно разделить, что агент получает сам (хуки), а что запрашивает (инструменты MCP, скиллы, команды), так, чтобы польза была максимальной при минимальном расходе контекста.

Вход:
- [[ADR-001 Что берём из разобранных решений]] — раздел 7 «Интерфейс для агента», противоречия К4, К5, К10, допущения Д12–Д14;
- [[ADR-002 Локальные модели для простых задач]] — раздел 6: команда включения модели, пометка `source` в ответах;
- [[ADR-004 Своё ядро на Rust]] и [[ADR-005 Поставка одним бинарником]] — один Rust-бинарник `codegraph` с подкомандами `index`, `query`, `mcp` (stdio) и `hook <событие>`:
  - хуки Claude Code вызывают его напрямую, без Node;
  - плагин — папка `plugin/` с `.claude-plugin/plugin.json`, `.mcp.json`, `hooks/hooks.json` и скиллами;
  - бинарник лежит в `plugin/bin/`.

**Ограничения.**
- Плагин Claude Code, не свой агент. Прототип закрытый, пользователь один.
- 5–8 инструментов MCP (ADR-001, К4).
- Хуки не выдают `permissionDecision` и ничего не блокируют (ADR-001, К10).
- Подмешивание контекста к каждому запросу по умолчанию выключено (ADR-001, К5).
- В auto memory Claude Code не пишем, `CLAUDE.md` не трогаем (ADR-001, раздел 7).
- Основная ОС — Windows: без bash, демона и своих портов.
- Ещё не приняты:
  - модель графа — ключи узлов, виды связей ([[F03-06 Архитектура графа и конвейер индексации]]);
  - формат знаний ([[F03-03 Хранение индекса и знаний]], [[F03-05 Форматы хранения знаний и их жизнь]]).

**Образцы** (отчёты в `Docs/Research/`):
- Graft (01 §1): 6 инструментов, их описания ≈ 0,7 тыс. токенов; `instructions` до ~1000 символов; хуки `SessionStart`, `UserPromptSubmit`, `PostToolUse` на правку, `Stop`.
- `colbymchenry/codegraph` (04 §2.1): по умолчанию один инструмент `explore`, инструкции передаются в `initialize`.
- claude-mem (02): на старте — оглавление «ID · время · тип · заголовок», дальше цепочка `search → timeline → get`; контекст к файлу при чтении, не чаще раза за сессию.
- CRG (04 §2.4): честная пометка на пустом ответе.
- Continue (04 §3.4): агенту лучше даются инструменты, которые он вызывает сам, чем подмешанный контекст.

**Факты из документации Claude Code** (сверено 2026-09-29 по `code.claude.com/docs/en/hooks`, `/mcp`, `/skills`, `/plugins-reference`):

| Факт | Что это значит для нас |
|---|---|
| При поиске инструментов (tool search, включён по умолчанию) на старте сессии загружаются только имена инструментов и `instructions` сервера. Схемы подгружаются через `ToolSearch`. Описание каждого инструмента и `instructions` обрезаются на 2048 символах | `instructions` — главный канал «как пользоваться». Д13 подтверждено документацией |
| Инструмент можно пометить `_meta["anthropic/alwaysLoad"]: true`: его схема грузится сразу | Входной `explore` грузим сразу, остальные — отложенно |
| Выход MCP: предупреждение при > 10 000 токенов, предел 25 000 | Наши бюджеты ответа — не больше 8000 токенов |
| `additionalContext` есть у `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolBatch`, `SubagentStart`, `Stop`. У `PreToolUse` и `PostToolUse` текст встаёт рядом с результатом инструмента | Подсказка из `PreToolUse` на Grep приходит вместе с результатом grep |
| `additionalContext` и простой stdout ограничены 10 000 символов; длиннее — в файл с превью 2000 символов | Наши вставки ≤ 2000 символов, до предела далеко |
| Асинхронный хук (`async: true`) не может ничего решать; его `additionalContext` приходит только на следующем ходе | Д14 закрыто документацией: подсказки к чтению и поиску делаем синхронными с жёстким бюджетом времени |
| `additionalContext` у `Stop` продолжает разговор: агент получает его и продолжает работу | Хук `Stop` не возвращает ничего, иначе он удлиняет каждый ход |
| Выход 2 у `PreToolUse` блокирует вызов | Наши хуки всегда выходят с кодом 0 |
| `SessionEnd`: общий бюджет 1,5 с; `timeout` у хуков плагина этот бюджет не поднимает; вывод отбрасывается | В `SessionEnd` — только запуск отсоединённого процесса |
| `UserPromptSubmit`: тайм-аут по умолчанию 30 с, хук ждут перед каждым запросом | Любая задержка здесь ощущается на каждом сообщении |
| Поле `if` (правило вида `Read(**/*.prefab)`) фильтрует вызов хука по аргументам инструмента | Хук чтения ставим только на ассеты Unity |
| У хуков плагина есть `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}`, `${CLAUDE_PROJECT_DIR}`. Exec-форма (`command` + `args`) работает без оболочки и требует настоящий исполняемый файл | Хуки вызывают `plugin/bin/codegraph` в exec-форме — это совпадает с поставкой по ADR-005 |
| Инструменты MCP из плагина называются `mcp__plugin_<плагин>_<сервер>__<инструмент>` | Имена плагина и сервера делаем короткими |
| Скилл с `disable-model-invocation: true` не кладёт описание в контекст; описание обычного скилла обрезается на 1536 символах | Команды плагина ничего не стоят; модели доступен один скилл с коротким описанием |
| Документация советует писать `additionalContext` утверждениями о фактах, а не приказами: текст «системных команд» может сработать на защиту от промпт-инъекций | Вставки хуков — данные с пометкой «не инструкции» |
| При `--resume` вставки из середины сессии воспроизводятся из записи, а `SessionStart` запускается заново с `source: resume` | В середине сессии не вставляем данные, которые быстро устаревают, без пометки времени |

## Решение

### 0. Правила интерфейса

1. **Каналы.**
   - Хуки подают **факты**, которые нужны в конкретный момент.
   - Инструменты отдают **ответы на вопросы** агента.
   - Команды выполняют **действия пользователя** и в контексте места не занимают.
   - Скилл — **подробные приёмы работы**, загружается по требованию.
2. **Один бинарник на всё** (ADR-004, ADR-005):
   - `codegraph mcp` — сервер MCP;
   - `codegraph hook <событие>` — хуки;
   - `codegraph index` и `codegraph query …` — команды плагина.
   Хуки и сервер работают с одним SQLite-индексом проекта. Своего демона и портов нет.
3. **Хуки ничего не решают.**
   - Не возвращают `permissionDecision`, `decision: "block"`, `continue: false`, `updatedInput`, `updatedToolOutput`.
   - Всегда выходят с кодом 0; ошибки пишут в `${CLAUDE_PLUGIN_DATA}/logs/`.
   - Не успели в свой бюджет времени — молчат.
4. **Бюджеты.** Лимит символов у каждой вставки, общий лимит вставок хуков на сессию — **6000 токенов** (≈ 20 тыс. символов). После него хуки дают одну строку: «ещё N предупреждений — вызови impact».
   - Повторов нет: одна и та же подсказка к символу, файлу или идентификатору выдаётся один раз за сессию.
   - Состояние сессии (счётчик бюджета, что уже показано) лежит в `${CLAUDE_PLUGIN_DATA}/sessions/<session_id>.json`.
5. **Текст вставок** начинается с `[codegraph]` и содержит только утверждения. Знания проекта, журнал и документы помечены как данные из репозитория (ADR-001 раздел 5: сгенерированный текст недоверенный).
6. **Каждый ответ инструмента:**
   - первой строкой — состояние индекса и ID ответа;
   - на каждой связи — метка уверенности и источник;
   - на пустом ответе — список слепых зон (приём CRG);
   - на результате модели — пометка `[model]` (ADR-002).
7. **Не трогаем** `CLAUDE.md`, auto memory и `settings.json`. Хуки и сервер поставляются в плагине (`plugin/hooks/hooks.json`, `plugin/.mcp.json`), поэтому код слияния настроек Graft (`settings-merge.ts`) не нужен.

**Рабочие имена** (окончательные — в [[F-13 Публикация для сообщества]]):
- плагин — `codegraph`, ключ сервера MCP — `cg`;
- полные имена инструментов — `mcp__plugin_codegraph_cg__<имя>`;
- команды — `/codegraph:<имя>`;
- бинарник — `codegraph` (ADR-005).

### 1. Инструменты MCP

Сервер — `codegraph mcp`, долгоживущий процесс по stdio. Его запускает Claude Code из `plugin/.mcp.json`, по одному на сессию. Инструменты появляются по слоям:
- MVP-1 — `explore`, `inspect`, `refs`, `impact`;
- MVP-2 — `recall`, `remember`;
- после MVP — седьмой, `check`, для [[F-09 Проверка изменений]].

Восьмое место — запас на итоги F-02: например, отдельный `unity`, если агент не находит связи Unity через `refs`.

**Сводка**

| Инструмент | Когда агент вызывает | Вход (главное) | Бюджет ответа, токенов (по умолчанию / максимум) | Слой | Входной |
|---|---|---|---|---|---|
| `explore` | Любой вопрос «где, что, как устроено» по коду, ассетам и документам — вместо цепочки grep + чтение | `query?`, `scope?`, `kinds?`, `detail?`, `budget?` | 1500 / 6000 | MVP-1 | **да**, схема грузится сразу |
| `inspect` | Нужен один символ, файл, ассет или раздел документа целиком или его оглавление без тел | `target`, `view?`, `neighbors?`, `budget?` | 1200 / 8000 | MVP-1 | нет |
| `refs` | «Кто использует X» и «что использует X», в том числе из сцен и префабов | `target`, `direction?`, `depth?`, `edges?`, `include_ambiguous?`, `budget?` | 1500 / 6000 | MVP-1 | нет |
| `impact` | Перед правкой публичного символа, сигнатуры, сериализованного поля или метода, который вызывает Unity; после серии правок — по `git diff` | `symbols?` \| `files?` \| `diff?`, `depth?`, `tests?`, `summary_only?`, `budget?` | 2000 / 8000 (`summary_only` ≈ 300) | MVP-1 | второй вход — перед правкой |
| `recall` | Перед тем как заново решать задачу; когда нужен прошлый опыт, решение или тупик | `query?`, `mode?` (`index`/`get`/`timeline`), `ids?`, `anchor?`, `scope?`, `filters?`, `limit?` | `index`: 20 строк ≈ 1500; `get`: ≤ 800 на запись | MVP-2 | нет |
| `remember` | Принято решение, найдена ловушка или тупик; оценка прошлого ответа или записи | `type`, `title`, `body`, `level?`, `bind?`, `tags?`, `supersedes?` \| `feedback` | ответ ≤ 100 | MVP-2 | нет |

**Общие правила ответа** (все инструменты):
- **Формат** — компактный текст строками, а не JSON: меньше токенов и легче читать.
- **Первая строка** — `index: fresh | refreshed N files | building 45% | partial` и ID ответа `ans:A-xxxx` (для оценки ответа в `remember`).
  - Перед ответом сервер сверяет отпечаток рабочего дерева и заново хэширует файлы, из которых собран ответ (ADR-001 раздел 1).
- **ID символа** — стабильный ключ вида `путь#Класс.метод` (ADR-001 раздел 5). Точную форму задаёт [[F03-06 Архитектура графа и конвейер индексации]]; для агента ключ непрозрачен. Ассет — путь, GUID можно дать на вход.
- **ID записи памяти** — непрозрачная строка с префиксом уровня:
  - `J-…` — журнал;
  - `K-…` — знания проекта;
  - `G:<база>/…` — глобальная база: своя или подключённая.
- **Метки связей** — `[E]`, `[I]`, `[A]` (EXTRACTED, INFERRED, AMBIGUOUS). Источник, если это не tree-sitter: `[E lsp]`, `[E unity]`, `[I git]`, `[I model]`. Неоднозначные связи (`[A]`) показываются только по запросу и как кандидаты.
- **Бюджет** соблюдает сервер: лишнее обрезается строкой `…+N (увеличь budget или сузь scope)`.
- **Пустой ответ** всегда содержит строку `blind spots:` — почему граф мог не увидеть связь: файл не проиндексирован, граф отстаёт, у языка известная слепая зона, строковый вызов с нелитеральным аргументом.
- **Аннотации MCP:** у всех инструментов, кроме `remember`, `readOnlyHint: true`.
- **Длина описания** одного инструмента — ≤ 350 символов, у каждого параметра — ≤ 80 символов, по-английски.

#### 1.1. `explore` — входной

Один вызов заменяет цепочку grep → чтение. Без `query` возвращает карту репозитория (L0): модули, ранжированные персонализированным PageRank по файлам из `git status` и недавнего журнала (ADR-001 раздел 1).

Вход:
- `query` (string, необязательно) — текст, имя, `путь#Символ` или путь; ищет по символам, ассетам, заголовкам документов (FTS5/BM25 + граф);
- `scope` (string) — папка или модуль, например `Assets/Scripts/UI`;
- `kinds` (`code`|`asset`|`doc`)[];
- `detail` — `map` | `signatures` (по умолчанию) | `snippets` (≤ 8 строк кода у первых трёх);
- `budget` (int).

Выход (сокращённо):
```
index: fresh · ans:A-7c1 · C# 1210 · TS 402 · Unity 318 prefabs/12 scenes
1. Assets/Scripts/Player.cs#Player.Jump  method  L41-67  void Jump(float force)
   callers 3 · Unity 1: Menu.prefab › JumpButton.onClick [E unity] · tests 1
2. Assets/Scripts/JumpController.cs#JumpController  class  L10-120
   ...
notes: K-3f9a «Койот-тайм 0.1 с» (project) · J-0412 dead_end (journal)
more: refs("Assets/Scripts/Player.cs#Player.Jump") · inspect(...)
```

#### 1.2. `inspect`

Уровни L1/L2 для одного узла графа любого вида.

Вход:
- `target` (string, обязательно) — ID символа, путь файла, путь ассета (`.unity`, `.prefab`, `.asset`), GUID или `путь.md#заголовок`;
- `view` — `outline` (по умолчанию для файлов и ассетов) | `signature` (по умолчанию для символов) | `body` | `full`;
- `neighbors` (bool, по умолчанию `true`) — связи первого круга;
- `budget`.

Что возвращает для разных узлов:
- **символ** — сигнатура, документирующий комментарий, строки, соседи по группам (вызывающие — первые 5 и число, вызываемые, переопределения, тесты, места в Unity, заметки);
- **файл** — оглавление: сигнатуры без тел;
- **ассет** — как в инспекторе: объекты → компоненты с классом скрипта вместо GUID, UnityEvent → метод, вложенные префабы и варианты, где используется;
- **документ** — дерево заголовков и упоминания кода.

```
index: fresh · ans:A-7c2
Assets/UI/Menu.prefab  prefab (variant of BaseMenu.prefab)
Canvas
  JumpButton: Button → onClick: Menu.OnJumpPressed [E unity]
  Title: TMP_Text
MenuController (Assets/Scripts/UI/MenuController.cs) on Canvas
used by: Main.unity, Pause.unity
```

#### 1.3. `refs`

Вход:
- `target` (обязательно);
- `direction` — `in` (по умолчанию) | `out`;
- `depth` — 1–3 (по умолчанию 1);
- `edges` — виды связей: `calls`, `imports`, `inherits`, `references`, `unity_script`, `unity_event`, `prefab_nesting`, `asset_ref`, `serialized_field`, `doc_mention`, `co_change`. По умолчанию все, кроме `co_change`. Точный список следует модели графа из F03-06;
- `include_ambiguous` (bool, по умолчанию `false`);
- `budget`.

```
index: fresh · ans:A-7c3
in(Assets/Scripts/UI/Menu.cs#Menu.OnJumpPressed) depth 1 · 3 refs
Assets/UI/Menu.prefab   JumpButton.onClick   unity_event [E unity]
Assets/UI/Pause.prefab  Resume.onClick       unity_event [E unity]
Assets/Scripts/Input/KeyRouter.cs:L55  calls [I]
ambiguous: 1 (include_ambiguous=true to list)
```

#### 1.4. `impact` — последствия правки

Вход — один из трёх вариантов:
- `symbols` (string[]);
- `files` (string[]);
- `diff` — `working` (по умолчанию) | `staged` | `<base>..<head>`.

Параметры:
- `depth` — 1–3 (по умолчанию 2);
- `tests` (bool, `true`);
- `summary_only` (bool);
- `budget`.

Что считается (ADR-001 раздел 2):
- вид изменения: сигнатура, тело, удаление, переименование, сериализованное поле;
- глубина 1 — «сломается», глубина 2 — «вероятно затронет»;
- затронутые ассеты Unity;
- тесты: `changed` / `stale` / `none`;
- файлы, которые обычно меняются вместе (`co_change`);
- риск с причинами;
- знания, привязанные к символу (возможно устарели);
- слепые зоны.

Для обхода подходит рекурсивный SQL из ue-xray (`impact.rs`, ADR-004).

```
index: fresh · ans:A-7c4 · diff: working (2 files, 3 symbols)
Player.Jump(float) → Jump(float,bool)  signature
 d1 breaks: JumpController.Tick [E] · Menu.prefab › JumpButton.onClick (UnityEvent) [E unity]
 d2 likely: InputRouter.OnPress [I]
 tests: PlayerTests.JumpHeight — exists, not touched (stale)
 co-change: Assets/Prefabs/Player.prefab (5 of 7 commits)
 risk 0.62: UnityEvent refs, no direct tests
 knowledge: K-3f9a bound to Player.Jump — code changed since, verify
 blind spots: Resources.Load(name) non-literal in Spawner.cs:88
```

#### 1.5. `recall` — память трёх уровней

Цепочка claude-mem `search → timeline → get` собрана в один инструмент с параметром `mode`.

Вход:
- `query` (для `index`);
- `mode` — `index` (по умолчанию) | `get` | `timeline`;
- `ids` (для `get`);
- `anchor` и `window` (для `timeline`);
- `scope` — `journal` | `project` | `global` | `all` (по умолчанию `all`); `global` включает подключённые базы, фильтр `bases`;
- `filters` — `type[]`, `tags[]` (технологии), `bound` (символ или файл), `since`;
- `limit`.

```
index: fresh · ans:A-7c5 · scopes: journal, project, global(me, ivan) · 3 of 12
J-0412  09-20  journal  dead_end  «OverlapCircle в FixedUpdate даёт ложные касания»  Player.cs
K-3f9a  08-02  project  decision  «Койот-тайм 0.1 с»  bound Player.Jump · stale
G:ivan/unity-ui-07  global  recipe  «UnityEvent теряет обработчик при переименовании метода»  Unity 2022.3
next: recall(mode="get", ids=["K-3f9a"])
```

В режиме `get` — полный текст и происхождение:
- коммит, файлы, автор;
- статус `active` / `stale` / `superseded`;
- источник: агент, человек или `[model]`.

#### 1.6. `remember` — запись и оценка

Вход в режиме записи:
- `type` — `decision` | `gotcha` | `dead_end` | `problem_solution` | `trade_off` | `fact` | `note`;
- `title`;
- `body` (≤ 2000 символов);
- `level` — `journal` (по умолчанию) | `project`;
- `bind` — ID символов и файлов;
- `tags`;
- `supersedes`.

Режим оценки: `feedback: {target: "ans:A-7c4" | "K-3f9a", verdict: useful | dead_end | corrected, note?}` — приём Graphify `save-result → reflect`.

Правила:
- `level: project` создаёт **черновик** знания в рабочей копии и ничего не коммитит: в git запись попадает только коммитом человека (ADR-001 раздел 5).
- В глобальную базу инструмент **не пишет**: только командой `/codegraph:promote`.
- До записи — фильтр секретов и тегов `<private>`.
- Перед созданием — поиск похожих; найденное показывается как подсказка, автозамены нет.

```
saved draft K-7c21 (project, uncommitted) · secrets filter: clean
similar: K-3f9a «Койот-тайм 0.1 с» — pass supersedes="K-3f9a" if this replaces it
```

### 2. Текст `instructions` для MCP `initialize`

Готовый текст, ≈ 1050 символов (предел Claude Code — 2048). Написан по-английски: для модели так в 1,5–2 раза меньше токенов, и текст пригоден для сообщества. Отвечает агент всё равно на языке пользователя. Если имена плагина или сервера поменяются, строка `select:` правится вместе с ними.

```text
codegraph: local code graph + memory for this repo (C# with Unity scenes/prefabs, JS/TS, Go, Rust, Markdown/PDF). The index refreshes before each query; every answer starts with an index status line.
- Where/what/how questions about code: call explore first, instead of grep+read chains.
- Before changing a public method, signature, serialized field or anything Unity calls: call impact. It sees prefab/scene/UnityEvent links grep misses.
- refs: who uses X / what X uses. inspect: outline of one symbol, file or asset.
- Before re-solving a problem: recall (journal, project knowledge, global bases). Index first, then mode=get by id.
- Decisions, gotchas, dead ends: remember. Project knowledge becomes an uncommitted draft.
Load all at once: ToolSearch "select:mcp__plugin_codegraph_cg__inspect,mcp__plugin_codegraph_cg__refs,mcp__plugin_codegraph_cg__impact,mcp__plugin_codegraph_cg__recall,mcp__plugin_codegraph_cg__remember".
Labels: E extracted, I inferred, A ambiguous (candidates, not facts). Empty result: read blind spots, then grep.
```

В MVP-1 строки про `recall` и `remember` и их имена в `select:` сервер не выдаёт: текст собирается из включённых слоёв.

### 3. Хуки

Все хуки — подкоманды бинарника: `codegraph hook <событие>`, JSON на stdin, JSON на stdout, exec-форма без оболочки. Rust-бинарник стартует за миллисекунды (ADR-005), поэтому бюджет времени уходит на запрос к SQLite, а не на запуск. Внутренний срок у каждого хука меньше тайм-аута: не успел — выходит молча.

| Событие | Отбор | Режим | Тайм-аут в `hooks.json`, с | Цель p95 | Что делает | Что получает агент | Лимит вставки |
|---|---|---|---|---|---|---|---|
| `SessionStart` | `startup\|resume\|clear\|compact` | синхронно | 10 | ≤ 500 мс | Проверяет индекс; при необходимости запускает `codegraph index` в фоне; собирает сводку | Состояние индекса, карта L0; в MVP-2 — оглавление журнала и счётчики знаний | 2000 символов (≈ 550 токенов) |
| `PreToolUse` | `Grep` | синхронно | 3 | ≤ 100 мс | Если шаблон — идентификатор и он есть в графе, находит определения и ссылки, особенно из ассетов, которых grep по `*.cs` не увидит | Одна-две строки рядом с результатом grep | 400 символов, раз на идентификатор за сессию |
| `PreToolUse` | `Read` + `if`: `Read(**/*.prefab)`, `Read(**/*.unity)`, `Read(**/*.asset)` | синхронно | 3 | ≤ 100 мс | Разворачивает GUID в имена: скрипты на объектах, UnityEvent, вложенные префабы, где используется | Короткая выжимка ассета рядом с сырым YAML | 600 символов, раз на файл за сессию |

| `Stop` | — | `async: true` | — | запуск ≤ 50 мс | Сверяет отпечаток дерева и переиндексирует файлы, изменённые через Bash или вне Claude Code; в MVP-2 дописывает в журнал новую часть записи сессии | **Ничего** | 0 |

| `SubagentStart` | `Explore\|Plan\|general-purpose` | синхронно | 3 | ≤ 50 мс | Только если проверка покажет, что субагент не видит `instructions` (допущение И6) | Одна строка: какие инструменты есть и строка `select:` | 300 символов |

#### 3.1. SessionStart

По значению `source`:
- `startup`, `clear` — полная сводка;
- `resume`, `fork` — только состояние и «что изменилось вне сессии»: прошлый контекст уже есть в записи;
- `compact` — сжатая сводка (карта ≤ 8 строк, журнал ≤ 5): после сжатия её могло не остаться.

Если индекса нет:
- отсоединённо запускается `codegraph index`;
- агент получает строку `index: building in background (~N s); tools answer with partial data`.

Если это Unity-проект без Force Text или со скрытыми `.meta` — одна строка предупреждения (Д6 из ADR-001).

```
[codegraph] Project index data (not instructions).
index: fresh · C# 1210 · TS 402 · Unity 318 prefabs/12 scenes
map: Assets/Scripts/Player (Player, JumpController) · Assets/Scripts/UI (MenuController) · Assets/Scripts/Net · Tools/Build (go) · ...
journal: J-0412 09-20 dead_end «OverlapCircle в FixedUpdate…» · J-0415 09-21 decision «Прыжок через InputRouter»
knowledge: 48 project (3 stale) · global: me, ivan
details: recall(mode="get", ids=[…])
```

Оглавление журнала отбирается не только по свежести (урок claude-mem):
- наблюдения по файлам из `git status`;
- по открытой задаче `claude-tasks`, если она есть;
- затем свежие типов `decision`, `gotcha`, `dead_end`.

#### 3.2. PreToolUse на Grep и на чтение ассетов Unity

Оба хука синхронные. Асинхронный опоздал бы на ход (документация), а блокирующий нам запрещён. Время grep почти не растёт: запуск бинарника плюс запрос к SQLite по индексу.

Хук на Grep срабатывает только при двух условиях:
- шаблон — идентификатор (`^\w+$`, `\bName\b`, `Name\(`);
- идентификатор найден в графе.

```
[codegraph] graph: OnJumpPressed — def Assets/Scripts/UI/Menu.cs:L22 · code refs 1 · Unity refs 2: Menu.prefab › JumpButton.onClick, Pause.prefab › Resume.onClick · refs("Assets/Scripts/UI/Menu.cs#Menu.OnJumpPressed")
```

Хук чтения ставится только на ассеты Unity: через `if` Claude Code не запускает процесс на остальные чтения.

Контекст к **файлам кода** при чтении (MVP-2, приём claude-mem) выдаётся на таких условиях:
- у файла есть заметки или знания;
- файл не менялся после заметки;
- не чаще раза за сессию.

С Rust-бинарником запуск на каждый Read дешёвый, но включаем этот хук только если [[F02-02 Скрипт прогона набора проверок]] покажет пользу вставки (И5). Иначе эти заметки агент видит через оглавление на старте и `recall`.

#### 3.3. PostToolUse на правку

Вставка появляется только в одном из случаев:
- изменились сигнатура, имя или видимость;
- символ удалён;
- переименовано сериализованное поле — тогда совет `[FormerlySerializedAs]`;
- изменилось имя метода, на который ссылается UnityEvent или Animation Event;
- у символа есть зависимые вне файла или в ассетах;
- к символу привязано знание.

На правку только тела без таких признаков хук молчит: детали можно получить через `impact`. Повтор с тем же набором зависимых не выдаётся.

```
[codegraph] after edit Assets/Scripts/Player.cs: Player.Jump(float) → Jump(float,bool)
d1: JumpController.Tick [E] · AI/BotBrain.Act [I] · Menu.prefab › JumpButton.onClick (UnityEvent) [E unity]
tests: PlayerTests.JumpHeight — not touched (stale)
knowledge: K-3f9a bound to Player.Jump — may be outdated
more: impact(symbols=["Assets/Scripts/Player.cs#Player.Jump"])
```

Если переиндексация не успела за 1 с:
- хук отдаёт `index: updating, run impact later`;
- работа доводится отсоединённым процессом.

Запись в индекс из хука и из сервера MCP идёт через один SQLite: WAL и замок на запись (И10).

#### 3.4. Stop и SessionEnd

`Stop` срабатывает после каждого хода, поэтому он асинхронный и **молчаливый**:
- `additionalContext` у `Stop` заставил бы агента продолжать ход;
- `decision: "block"` нам запрещён.

Что он делает:
- **Свежесть индекса.** Сверяет отпечаток рабочего дерева; так ловятся правки через Bash, `git checkout` и внешние редакторы. Отдельный хук на Bash не нужен.
- **Журнал (MVP-2).** Дописывает события из новой части записи сессии (`transcript_path`, с сохранённого смещения) тем же разборщиком, что импорт истории (ADR-001 раздел 4). Это один процесс на ход вместо процесса на каждый вызов инструмента.
- **Запасной путь**, если формат записи окажется нестабильным (И7): асинхронный `PostToolUse` на `.*` «записал и вышел» (≤ 500 мс).
- **Защита от наложений.** У асинхронных хуков нет защиты от повторов, поэтому второй запуск видит файл-замок и выходит.

`SessionEnd` ограничен 1,5 с на все хуки. Поле `timeout` у плагина этот бюджет не поднимает. Поэтому хук только запускает отсоединённый процесс `codegraph` (Л5 из ADR-002) и сразу выходит.

#### 3.5. UserPromptSubmit — не нужен в MVP

Не регистрируется: ноль процессов и ноль токенов на каждое сообщение (К5). Запуск Rust-бинарника дёшев, так что довод здесь — токены и шум, а не время.

Обоснование:
- то, что Graft подмешивает к запросу, у нас приходит точнее и позже — рядом с grep, чтением и правкой;
- на старте сессии агент уже получает карту и оглавление.

Замер: режим `light` проверяется в [[F02-02 Скрипт прогона набора проверок]]:
- только точные идентификаторы из текста запроса, найденные в графе;
- ≤ 400 символов;
- срок 1 с.

Если замер покажет пользу, хук добавляется в `hooks.json` с настройкой `userConfig.promptContext` (`off` по умолчанию).

#### 3.6. Каркас `plugin/hooks/hooks.json`

На Windows путь указывает на `codegraph.exe`; нужен ли явный суффикс `.exe` в `command` — И4.

```json
{
  "description": "codegraph: code graph and memory hints (never blocks)",
  "hooks": {
    "SessionStart": [{ "matcher": "startup|resume|clear|compact",
      "hooks": [{ "type": "command", "command": "${CLAUDE_PLUGIN_ROOT}/bin/codegraph", "args": ["hook", "session-start"], "timeout": 10 }] }],
    "PreToolUse": [
      { "matcher": "Grep", "hooks": [{ "type": "command", "command": "${CLAUDE_PLUGIN_ROOT}/bin/codegraph", "args": ["hook", "pre-grep"], "timeout": 3 }] },
      { "matcher": "Read", "hooks": [
        { "type": "command", "if": "Read(**/*.prefab)", "command": "${CLAUDE_PLUGIN_ROOT}/bin/codegraph", "args": ["hook", "pre-read-asset"], "timeout": 3 },
        { "type": "command", "if": "Read(**/*.unity)",  "command": "${CLAUDE_PLUGIN_ROOT}/bin/codegraph", "args": ["hook", "pre-read-asset"], "timeout": 3 },
        { "type": "command", "if": "Read(**/*.asset)",  "command": "${CLAUDE_PLUGIN_ROOT}/bin/codegraph", "args": ["hook", "pre-read-asset"], "timeout": 3 } ] }
    ],
    "PostToolUse": [{ "matcher": "Edit|Write|MultiEdit",
      "hooks": [{ "type": "command", "command": "${CLAUDE_PLUGIN_ROOT}/bin/codegraph", "args": ["hook", "post-edit"], "timeout": 5 }] }],
    "Stop": [{ "hooks": [{ "type": "command", "command": "${CLAUDE_PLUGIN_ROOT}/bin/codegraph", "args": ["hook", "stop"], "async": true }] }],
    "SessionEnd": [{ "hooks": [{ "type": "command", "command": "${CLAUDE_PLUGIN_ROOT}/bin/codegraph", "args": ["hook", "session-end"] }] }]

```

`plugin/.mcp.json`: сервер `cg` с `"command": "${CLAUDE_PLUGIN_ROOT}/bin/codegraph", "args": ["mcp"]`.

### 4. Скиллы и команды плагина

**Команды.** Это скиллы в `plugin/skills/` с `disable-model-invocation: true`:
- их описание в контекст не попадает, стоимость — 0 токенов, пока пользователь не вызовет команду;
- работу делает бинарник `codegraph`, скилл даёт `allowed-tools: Bash(${CLAUDE_PLUGIN_ROOT}/bin/codegraph *)`;
- если нужно суждение (обобщение, выбор, разбор конфликтов), команда работает через основного агента в текущей сессии.

| Команда | Назначение | Когда появляется |
|---|---|---|
| `/codegraph:setup` | Первый запуск. Определяет стек (Unity: Force Text, видимые `.meta`; Go, Rust, TS), строит индекс, добавляет папку индекса в `.gitignore`, ставит git-хуки `post-commit`, `post-merge`, `post-checkout` между маркерами (ADR-001 раздел 1), по согласию пользователя предлагает правило разрешения для инструментов только для чтения | MVP-1 |
| `/codegraph:status` | Состояние индекса: языки, число узлов и связей, устаревшие файлы, слепые зоны; включённые модули; расход вставок хуков за сессию | MVP-1 |
| `/codegraph:reindex [--full]` | Пересборка индекса: инкрементальная или полная | MVP-1 |
| `/codegraph:uninstall` | Снимает git-хуки между маркерами и по выбору удаляет индекс и данные плагина. Хуки Claude Code уходят вместе с плагином | MVP-1 |
| `/codegraph:model [on\|off\|status]` | Включение и выключение локальной модели по ADR-002: выбор Ollama или LM Studio, установка по клику, загрузка модели, пробный запрос | MVP-2 |
| `/codegraph:learn` | Журнал → знания проекта. Показывает кандидатов (`decision`, `gotcha`, `trade_off`, `problem_solution`, уроки `reflect`); агент готовит черновики, человек выбирает; результат — незакоммиченные записи | MVP-2 |
| `/codegraph:promote <id…>` | Знания проекта → личная глобальная база. Основной агент обобщает рецепт и убирает пути, `origin` и имена проекта; человек подтверждает; модель не участвует (ADR-002) | MVP-2 |
| `/codegraph:bases list \| attach <путь> [--name] \| detach <имя> \| merge <имя> \| export <ids\|--tag> <путь>` | Базы коллег: подключить или отключить базу, слить подключённую в свою (поиск дублей, разбор конфликтов, происхождение сохраняется), выгрузить выбранные записи для передачи | MVP-2 |
| `/codegraph:import-history` | Импорт прежних сессий Claude Code (JSONL, хранятся ≤ 30 дней) в журнал через фильтр приватности | MVP-2 |

**Скилл для модели** — один, `codegraph:guide`:
- описание ≤ 250 символов, всегда в контексте (≈ 70 токенов): «How to use codegraph for multi-file refactors, renames touching Unity assets, bug hunts with past context, and recording or promoting knowledge»;
- тело ≤ 6 КБ: порядок работы для переименования и рефакторинга с Unity, для расследования с `recall`, что стоит записывать и на каком уровне, как читать метки и слепые зоны;
- справки в `references/` по требованию, каждая ≤ 8 КБ: `unity.md` (виды связей, `[FormerlySerializedAs]`, слепые зоны), `memory.md` (уровни, типы, подключённые базы), `answers.md` (формат ответов и ID).

Это приём Graphify «лёгкий skill + `references/`» без его 10 тыс. токенов.

**Субагенты.**
- Инструменты MCP доступны встроенным субагентам (`Explore`, `Plan`, `general-purpose`) без настройки.
- Своих агентов в MVP плагин не ставит.
- Правило для будущих агентов плагина: в `tools` — только чтение (`explore`, `inspect`, `refs`, `impact`, `recall`), без `remember` (профили CodeGraph и CBM).

### 5. Оценка расхода контекста

Оценка грубая: английский ≈ 4 символа на токен, текст с путями и идентификаторами ≈ 3,5. Точный замер — И8.

| Что | Когда платим | Токены |
|---|---|---|
| `instructions` сервера | каждая сессия | ≈ 260 |
| Имена 6 инструментов в списке отложенных | каждая сессия | ≈ 80 |
| Схема `explore` (`alwaysLoad`) | каждая сессия | ≈ 250 |
| Описание скилла `codegraph:guide` | каждая сессия | ≈ 70 |
| Команды `/codegraph:*` (9) | — | 0 |
| Вставка `SessionStart` | каждая сессия, повтор после сжатия | 300 в MVP-1, до 550 в MVP-2 |
| **Итого постоянно** | | **≈ 1,0–1,2 тыс.** |
| Схемы остальных 5 инструментов | один раз, при первом `ToolSearch` | ≈ 1,1 тыс. |
| `PostToolUse` на правку | только при значимой правке | ≤ 220 за вставку |
| `PreToolUse` на Grep | только при попадании, раз на идентификатор | ≤ 110 |
| `PreToolUse` на ассет Unity | раз на файл | ≤ 170 |
| Все вставки хуков за сессию | жёсткий потолок | ≤ 6 тыс. |
| Ответы инструментов | по выбору агента | 1,2–2 тыс. по умолчанию, ≤ 8 тыс. |

Пример на час работы: 30 правок, из них ~12 значимых; 15 поисков, из них ~6 с попаданием; 5 чтений префабов. Выходит ≈ 1,1 (постоянно) + 1,1 (схемы) + 2,6 + 0,7 + 0,85 ≈ **6,4 тыс. токенов** без ответов инструментов.

Для сравнения:
- у Graft только описания инструментов ≈ 0,7 тыс., плюс подмешивание на каждый запрос;
- у CodeGraph описания 42 инструментов — 6–7 тыс. в каждой сессии;
- у ue-xray 127 инструментов (ADR-004);
- у `colbymchenry/codegraph` по их README к концу сессии в контексте на ~80% больше, чем у агента, который просто читает файлы.

### 7. Что это меняет в плане

Это предложения лиду; файлы задач не правились.

- **[[F-04 Карта кода]].** Первая impl-задача — каркас плагина:
  - `plugin/.mcp.json` и `codegraph mcp` с `explore`, `inspect`, `refs`;
  - `codegraph hook …`, `plugin/hooks/hooks.json`, состояние сессии и бюджеты;
  - `/codegraph:setup`, `/codegraph:status`, `/codegraph:reindex`, `/codegraph:uninstall`;
  - проверка И1, И2, И4, И6.
- **[[F-05 Последствия правок]]:** `impact` и хук `PostToolUse` на правку.
- **[[F-10 Сцены и префабы Unity]]:** Unity-виды связей в `refs`, `inspect` для ассетов, хук чтения ассетов, Unity-часть хука на Grep.
- **[[F-06 Журнал работы агента]]:** `recall` (уровень журнала), `remember` с `level: journal` и `feedback`, запись журнала в `Stop` и `SessionEnd`, оглавление в `SessionStart`, `/codegraph:import-history`.
- **[[F-07 Знания проекта]]:** `remember` с `level: project`, `/codegraph:learn`.
- **[[F-14 Глобальная база знаний]]:** `/codegraph:promote`, `/codegraph:bases`.
- **[[F02-02 Скрипт прогона набора проверок]]:** замеры И3, И5, И8, И9 и режима `light`.

Допущения ADR-001 закрываются так:
- **Д13** — подтверждено документацией: при отложенных схемах `instructions` загружаются; остаётся практическая проверка И1.
- **Д14** — снято: контекст асинхронного `PreToolUse` приходит только на следующем ходе, поэтому хуки синхронные.
- **Д12** — уточнено оценкой в разделе 5 и переходит в И5.

## Отвергнутые варианты

- **Один инструмент `explore`**, как у `colbymchenry/codegraph`:
  - противоречит ограничению 5–8 инструментов;
  - `impact` по `git diff` и `remember` с явными параметрами в один «умный» запрос не укладываются.
  - Сама идея входного инструмента взята: `explore` грузится сразу и назван первым в `instructions`. Окончательно — по замеру И5.
- **Десяток и больше узких инструментов** (CodeGraph: 42 инструмента ≈ 6–7 тыс. токенов; ue-xray: 127; claude-mem: `search`, `timeline`, `get_observations`, `get_tool_uses` отдельно).
  - Цепочка памяти собрана в `recall` с параметром `mode`.
  - Отдельные инструменты на каждый уровень памяти заменены параметром `scope`.
  - Отдельный `unity` заменён видами связей в `refs` и ассетами в `inspect`.
- **Подмешивание контекста к каждому запросу (`UserPromptSubmit`) по умолчанию** (Graft) — токены и шум на каждое сообщение; agentmemory выключил это из-за расхода лимитов; Continue отказался в пользу инструментов (К5).
- **Асинхронный `PreToolUse` для подсказок к чтению** (claude-mem) — по документации контекст придёт только на следующем ходе, уже после чтения.
- **`permissionDecision: "allow"` или блокировка в хуках** (CodeGraph, claude-mem) — обходит разрешения Claude Code (К10).
- **`additionalContext` или `decision: "block"` в `Stop`** — продлевает каждый ход, тратит токены и может зациклиться. Пересборку делаем молча в фоне.
- **Хук на Glob** (ADR-001 раздел 7 его предлагал) — шаблоны имён файлов мало что дают графу; вставка была бы шумом.
- **Отдельный хук на Bash** (CRG: `update` после каждого Bash) — отпечаток рабочего дерева в `Stop` и перед каждым запросом ловит те же изменения, включая `git checkout`. Поле `bashEditDiff` к тому же в бета-версии и пишется не во всех режимах.
- **Запись журнала процессом на каждый вызов инструмента** (agentmemory, claude-mem) — остаётся только запасным путём (И7). Основной путь — разбор записи сессии в `Stop`.
- **Свой демон или HTTP-воркер** (claude-mem, agentmemory) — лишний процесс и порт, проблемы на Windows; сервер MCP и так живёт всю сессию, а хуки — быстрые подкоманды того же бинарника.
- **Хуки через обёртки на Node, bash или PowerShell** — лишний запуск интерпретатора; на Windows без Git Bash bash-хуки не работают (урок claude-mem). Бинарник вызывается напрямую.
- **Большой skill как основной интерфейс** (Graphify ≈ 10 тыс. токенов; SKILL.md Graft ≈ 9 КБ) — вместо него `instructions`, один лёгкий скилл и `references/` по требованию.
- **Инструкции в `CLAUDE.md` или auto memory** — `CLAUDE.md` пользователя не трогаем; `instructions` в `initialize` доходят и так.
- **Ресурсы и промпты MCP вместо инструментов и команд** — ресурсы агент сам почти не читает, промпты дублируют команды-скиллы.
- **Строка состояния (statusline)**, как у Graft — это настройка пользователя, одна на все плагины; состояние показывает `/codegraph:status`.
- **Запись `remember` сразу в глобальную базу или коммит знаний** — в git и в глобальную базу знания попадают только явным действием человека (ADR-001 разделы 5 и 5а; ADR-002: обобщение делает основной агент по команде).
- **JSON-ответы инструментов** — больше токенов на ключи и кавычки при той же информации; проверка — И9.
