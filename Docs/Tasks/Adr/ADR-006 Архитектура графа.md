# ADR-006 Архитектура графа

> **Решение:** граф — одно пространство узлов со стабильными строковыми ключами (код, ассеты Unity, документы, память) и рёбер с видом, источником, уверенностью и доказательством в SQLite из нескольких общих таблиц; строит его конвейер «обнаружение → раскладка проекта → извлечение фактов чистыми модулями языков (rayon, кэш по хэшу) → разрешение по всем фактам → запись одной транзакцией», а обновляет инкрементально по обратному индексу имён и зависимостей разрешения.
> **Почему:** так исправляются все системные ошибки ue-xray (целочисленные адреса, таблица на вид, разрешение при вставке, полная пересборка), новый язык или формат добавляется одним крейтом с общим трейтом, а обновление одного файла укладывается в сотни миллисекунд и годится для хука после правки.
> **Следствия:** первая impl-задача [[F-04 Карта кода]] создаёт воркспейс из раздела 5 и схему из раздела 4, модули пишутся против трейта из раздела 6 и проверяются на базах [[F02-03 Тестовые кодовые базы с ожидаемым графом]], инструменты [[ADR-003 Интерфейс для агента]] строятся поверх слоя запросов из раздела 10, а память ([[F-07 Знания проекта]]) привязывается к узлам через интерфейс раздела 11.

## Контекст

**Что решаем.** Модель графа, идентичность узлов, метки рёбер, схему хранения, конвейер индексации, инкрементальное обновление, слой запросов и интерфейс модуля языка — так, чтобы impl-задачи [[F-04 Карта кода]], [[F-05 Последствия правок]], [[F-10 Сцены и префабы Unity]], [[F-08 Документы в графе]] и тесты [[F02-03 Тестовые кодовые базы с ожидаемым графом]] начинались без повторного проектирования.

**Что уже решено.**
- Своё ядро на Rust, один бинарник `codegraph` (`index`, `query`, `mcp`, `hook`), каркас из ue-xray: `rusqlite` с `bundled` и FTS5, `rmcp`, `tree-sitter` 0.24, `rayon` — [[ADR-004 Своё ядро на Rust]], [[ADR-005 Поставка одним бинарником]]. Этим закрыт критерий «своё ядро или готовое» ([[F03-01 Своё ядро или готовый движок]]) и «язык ядра» ([[F03-02 Язык ядра и способ поставки]]).
- Приёмы: ADR-001 разделы 1–3, 6, 7 (разрешение без угадывания, метки `EXTRACTED`/`INFERRED`/`AMBIGUOUS`, неразрешённые ссылки с кандидатами, свежесть по отпечатку, офлайн-разбор YAML Unity, Markdown в тот же граф), противоречие К3 (неоднозначное — не в граф).
- Интерфейс агента — [[ADR-003 Интерфейс для агента]] (принят): инструменты `explore`, `inspect`, `refs`, `impact`, `recall`, `remember`; группы связей в `refs.edges`; метки `[E]`/`[I]`/`[A]` с источником. Ключ узла для агента непрозрачен; точную форму задаёт этот ADR.

**Уроки ue-xray** (`Docs/Research/08-ue-xray.md`, §3.5, §6). Два слоя «сырые факты → `graph_edges`» — удачная идея. Провальные решения:
1. узел адресуется `(тип, INTEGER id)`; `INSERT OR REPLACE` пересоздаёт строку и уводит ссылки; FTS со сдвигом `rowid` на 1 млн на тип;
2. таблица, импортёр и инструмент на каждый вид сущности (121 таблица, 127 инструментов);
3. разрешение вызова в момент вставки отдельным `SELECT` — зависимость от порядка;
4. производные таблицы (`graph_edges`, наследование, FTS) пересобираются целиком на каждое обновление;
5. у рёбер нет источника и уверенности;
6. уникальность по короткому имени (H6: два `BP_Door`).

**Масштаб наших баз** (`Bench/projects/`, подсчёт 2026-09-29): Chop Chop — 311 файлов `.cs` (~22 тыс. строк), 3649 `.meta`, 1210 текстовых `.prefab`/`.unity`/`.asset`, папка `Assets` — 340 МБ; excalibur — 606 `.ts`; nano — 77 `.go`; ggez — 73 `.rs`.

**Принципы лида** (2026-09-29): один граф со слоями; стабильные строковые ключи по образцу SCIP и хэш тела; сначала факты, потом связи; метки рёбер; конвейер с rayon и транзакцией; инкремент без полной пересборки (< 200 мс на файл); несколько общих таблиц SQLite; набор запросов; одинаковый трейт модулей; интерфейс привязки памяти. Ниже они развёрнуты в конкретику; отступления собраны в разделе 14.

**Чего здесь нет.** Формат и место хранения знаний и журнала — [[F03-03 Хранение индекса и знаний]], [[F03-05 Форматы хранения знаний и их жизнь]]. Список инструментов и формат ответов — ADR-003. Формат эталонов `Bench/README.md` ещё не написан ([[F02-01 Эталонные связи в наших проектах]]): раздел 12 оставляет для него адаптер.

## Решение

### 1. Модель графа

Один граф: узлы всех слоёв в одной таблице с одним пространством ключей, рёбра — в одной таблице. Вид — значение поля, а не таблица.

**Слои** (`nodes.layer`): `0 fs` — файлы; `1 code` — код; `2 unity` — ассеты и объекты Unity; `3 docs` — документы; `4 memory` — записи знаний и журнала.

**Виды узлов**

| Слой | Вид (`kind`) | Что это | Кто создаёт |
|---|---|---|---|
| fs | `file` | Любой проиндексированный файл | конвейер |
| code | `unit` | Сборка C# (`.asmdef`, `.csproj`, `Assembly-CSharp`), пакет npm, модуль Go, крейт Rust (цель сборки) | модуль языка по конфигу |
| code | `namespace` | Пространство имён C#, пакет Go | модуль языка |
| code | `module` | Модуль TS/JS (файл), модуль Rust (`mod`) | модуль языка |
| code | `class`, `struct`, `interface`, `trait`, `enum`, `delegate`, `type_alias` | Типы | модуль языка |
| code | `function`, `method`, `constructor`, `macro` | Исполняемые члены и свободные функции | модуль языка |
| code | `field`, `property`, `event`, `constant`, `enum_member`, `variable` | Данные (`variable` — уровень модуля) | модуль языка |
| unity | `asset` | Файл с `.meta`: сцена, префаб, ScriptableObject, материал, скрипт, клип… (`props.asset_type`, `props.importer`) | модуль Unity по `.meta` |
| unity | `game_object` | GameObject, если на нём есть MonoBehaviour, он корень префаба или на него ссылается MonoBehaviour или UnityEvent того же файла | модуль Unity |
| unity | `component` | Документ MonoBehaviour (класс 114) | модуль Unity |
| unity | `prefab_instance` | Документ PrefabInstance (класс 1001), в том числе корень варианта | модуль Unity |
| docs | `document`, `section` | Markdown-файл и раздел по заголовку (PDF — после MVP, тот же вид) | модуль Markdown |
| memory | `note` | Запись знаний или журнала (формат — F03-03/F03-05) | модуль знаний (MVP-2) |

Не узлы: локальные переменные и параметры (они — контекст типов в фактах), лямбды (их вызовы относятся к объемлющему методу), Transform и встроенные компоненты Unity (их классы — список `props.components` у `game_object`, ссылка на встроенный компонент адресуется узлом его GameObject с `props.component_class`), промежуточные GameObject без скриптов (их имена входят в `props.path` потомков: `Canvas/Panel/JumpButton`), заглушки `stripped` (разворачиваются в объект-источник, раздел 8.6).

Флаги узла (`nodes.flags`, биты): `external` (заглушка внешнего символа без объявления: `MonoBehaviour`, `std::fmt::Display`), `exported` (public / экспорт модуля / заглавная буква в Go / `pub`), `static`, `abstract`, `partial`, `test` (тестовый метод или файл), `entry` (вызывается извне кода — вид в `props.entry`: `unity_message`, `unity_editor`, `main`, `test`, `ffi`), `generated`.

**Виды рёбер.** Все рёбра, кроме `contains`, направлены от зависимого к зависимости: «src использует dst». Поэтому «кто пострадает от правки X» — это обход входящих рёбер X.

| Вид (`kind`) | От → к | Слой | Откуда берётся | Группа `refs.edges` (ADR-003) |
|---|---|---|---|---|
| `contains` | родитель → ребёнок | все | `nodes.parent_id` (строкой в `edges` не хранится) | — |
| `imports` | файл/модуль → модуль/пространство имён/пакет | code | `using`, `import`, `use` | `imports` |
| `depends_on` | unit → unit | code | ссылки `.asmdef`, `go.mod`, `Cargo.toml`, `package.json` | `imports` |
| `calls` | функция/метод → функция/метод/конструктор | code | вызов, `go f()` (`props.async`) | `calls` |
| `instantiates` | функция → тип | code | `new T()`, `T{}`, `T::new` через путь | `calls` |
| `references` | функция → функция/метод | code | метод как значение (`+= Handler`, `nameof`, передача колбэка) | `references` |
| `uses_type` | объявление → тип | code | типы полей, параметров, возврата, локальных, `typeof`, приведения, `GetComponent<T>`, `[RequireComponent]` (`props.via`) | `references` |
| `reads`, `writes` | функция → поле/свойство | code | доступ к полю | `references` |
| `inherits` | тип → базовый класс или структура (Go-встраивание: `props.embed`) | code | список баз | `inherits` |
| `implements` | тип → интерфейс/трейт | code | список баз; `impl Trait for T`; Go — по набору методов | `inherits` |
| `overrides` | метод → метод базы/интерфейса/трейта | code | `override`, явная и неявная реализация, методы `impl Trait`, Go по набору методов | `inherits` |
| `raises` | функция → событие/делегат | code | `E?.Invoke()`, `E()` у поля-события | `calls` |
| `handles` | метод-обработчик → событие | code | `E += Handler`, `E.AddListener(Handler)` | `calls` |
| `runs_script` | `component` → класс C# | unity | `m_Script` → `.meta` → `.cs` → класс | `unity_script` |
| `instance_of` | `prefab_instance` → `asset` префаба | unity | `PrefabInstance.m_SourcePrefab` | `prefab_nesting` |
| `variant_of` | `asset` варианта → `asset` базы | unity | корневой PrefabInstance без родителя | `prefab_nesting` |
| `removes_component` | `prefab_instance` → `component` источника | unity | `m_RemovedComponents` (цель в том же пространстве fileID) | `prefab_nesting` |
| `unity_ref` | объект/ассет/функция → ассет/объект | unity | любые `{fileID, guid}`, `m_AssetGUID`, `m_Modifications[].objectReference`, группы Addressables (`props.address`), `EditorBuildSettings` (`props.build_index`); из кода — литералы `Resources.Load`, `Addressables.Load*`, `SceneManager.LoadScene` | `asset_ref` |
| `unity_event` | объект (владелец события) → метод | unity | `m_PersistentCalls.m_Calls[]` (`props.mode`, `props.event`) | `unity_event` |
| `anim_event` | `asset` клипа → метод | unity | `.anim` `m_Events[].functionName` | `unity_event` |
| `serializes` | `asset` → поле | unity | ключи YAML сериализованных полей компонента | `serialized_field` |
| `references_type` | `asset` → тип | unity | `[SerializeReference]` `RefIds[].type` | `asset_ref` |
| `links_to` | раздел → документ/раздел/файл | docs | Markdown- и вики-ссылки, пути в тексте | `doc_mention` |
| `mentions` | раздел → узел кода или ассет | docs | имена в обратных кавычках | `doc_mention` |
| `co_change` | файл → файл | fs | история git (ADR-001 раздел 2: 6 месяцев, ≥ 3 совместных правок, доля ≥ 0,3, коммиты > 20 файлов пропускаются) | `co_change` |

### 2. Идентичность узла

**Ключ** — стабильная строка, единственный внешний адрес узла: в ответах инструментов, во входе `target`, в привязках памяти, в тестах. Внутренний `nodes.id` (rowid) наружу не выходит. Ключ вычисляется при извлечении из текста файла и его контекста (раздел 6, `FileCtx`) и не содержит номеров строк, порядковых номеров и хэшей.

Формат: `<схема>:<единица>:<дескриптор>`. Схема — язык или слой. Единица — сборка, пакет, модуль, крейт (аналог `package` у SCIP); для слоёв без единиц её нет. Дескриптор — в естественном синтаксисе языка, чтобы ключ читался агентом и человеком. Ключ для кода непрозрачен: разбирать его не нужно, родитель хранится в `nodes.parent_id`.

| Слой / язык | Правило | Пример |
|---|---|---|
| Файл | `file:<путь от корня>`; `/`, регистр как на диске | `file:Assets/Scripts/StateMachine/Core/StateMachine.cs` |
| C# сборка | `cs:<имя сборки>`; без `.asmdef` — `Assembly-CSharp`, в папке `Editor` — `Assembly-CSharp-Editor`, в `Plugins`/`Standard Assets` — `…-firstpass`; вне Unity — `AssemblyName` из `.csproj` | `cs:UOP1.StateMachine` |
| C# пространство имён | `cs:<сборка>:<Ns>` | `cs:UOP1.StateMachine:UOP1.StateMachine` |
| C# тип | `cs:<сборка>:<Ns>.<Тип>`; вложенный — через `+`, дженерик — арность через обратную кавычку, как в метаданных .NET (так же пишет Unity в `m_TargetAssemblyTypeName` и `[SerializeReference]`) | `cs:UOP1.StateMachine:UOP1.StateMachine.StateMachine`; ``cs:Assembly-CSharp:Game.Pool`1+Handle`` |
| C# член | `<тип>#<Имя>`; методы — всегда со списком параметров: последний сегмент имени типа, аргументы дженериков, `[]`, `?`, префиксы `ref `, `out `, `in `, `params `; конструктор `.ctor`, статический `.cctor`, индексатор `this[]`, явная реализация `IFoo.M`, дженерик-метод — с арностью | `cs:UOP1.StateMachine:UOP1.StateMachine.StateMachine#Awake()`; `cs:Assembly-CSharp:Game.Inventory#Add(Item,int)`; `cs:Assembly-CSharp:Game.Save#IDisposable.Dispose()`; `cs:Assembly-CSharp:Game.Player#_speed` |
| TS/JS (одна схема `ts` на семейство) | `ts:<пакет>:<путь модуля от корня пакета с расширением>[#<локальный путь>]`; пакет — `name` ближайшего `package.json` или имя папки | `ts:excalibur:src/engine/Actor.ts`; `ts:excalibur:src/engine/Actor.ts#Actor.update`; `ts:game:src/main.ts#default` |
| Go | `go:<путь импорта пакета>[:<Имя>]`; метод — `Тип.Метод` без `*`; внешний тестовый пакет — суффикс `_test` | `go:github.com/lonng/nano/session`; `go:github.com/lonng/nano/session:Session.Close`; `go:github.com/lonng/nano/session:NewSession` |
| Rust | `rs:<крейт (цель сборки)>[:<путь модуля>::<Имя>]`; модуль по пути файла (`src/a/b.rs`, `src/a/b/mod.rs` → `a::b`); метод inherent-блока — `Тип::м`; метод реализации трейта — `<Тип as Трейт>::м`; макрос — `имя!` | `rs:ggez`; `rs:ggez:graphics::canvas::Canvas::draw`; `rs:ggez:graphics::canvas::<Canvas as Drawable>::draw` |
| Внешний символ (заглушка) | единица `ext`, дескриптор — полное имя как записано после разрешения `using` | `cs:ext:UnityEngine.MonoBehaviour`; `rs:ext:std::fmt::Display` |
| Unity ассет | `u:<guid>` из `.meta` | `u:661c491ac76af4b429f8a8c0e6e8c762` |
| Unity объект | `u:<guid>:<fileID>`; fileID — строкой со знаком, как в файле (64-битные числа, отрицательные бывают) | `u:661c491ac76af4b429f8a8c0e6e8c762:5054559148327267577`; `u:661c491ac76af4b429f8a8c0e6e8c762:-6233334297847596787` |
| Документ | `doc:<путь>`; раздел — `doc:<путь>#<путь слагов заголовков через />` | `doc:Docs/Design/Combat.md`; `doc:Docs/Design/Combat.md#урон/крит` |
| Запись памяти | `mem:<id записи>`; вид ID — F03-05 | `mem:K-3f9a` |

**Правила ключа.**
- Два объявления в одном файле с одинаковым ключом (ветки `#if UNITY_EDITOR`, `static` и не-`static` член TS с одним именем) — один узел с несколькими местами объявления (таблица `decls`).
- `partial`-класс C#, пространство имён C# и пакет Go объявлены в нескольких файлах — один узел, по строке `decls` на каждый файл; узел удаляется, когда у него не осталось объявлений.
- C#: ключ не зависит от пути файла — перенос `.cs` в другую папку (Unity сохраняет GUID) ключ не меняет, если не меняется сборка. TS: модуль — это файл, поэтому перенос меняет ключ; перепривязку памяти берёт на себя раздел 11.
- Ключ меняется при переименовании, смене пространства имён, сборки или списка параметров (C#). Это честно: для агента это другой символ; память переносится эвристикой «переехал» (раздел 11).
- Пути сравниваются без учёта регистра на Windows и macOS; в ключе хранится регистр с диска.
- Нормализация и формат ключа — часть контракта с памятью: их версия лежит в `meta.key_scheme`; смена версии — миграция привязок.

**Хэши** (xxh3-128; алгоритм и нормализация — `meta.hash_scheme`):
- `content_hash` файла — по байтам после снятия BOM; ключ кэша фактов.
- `body_hash` объявления — по последовательности листьев синтаксического дерева без комментариев и пробелов (переформатирование, смена CRLF/LF и комментарии хэш не меняют). Для объекта Unity — по тексту YAML-документа; для раздела документа — по тексту с нормализованными пробелами. Хэш узла с несколькими `decls` — хэш от хэшей мест в порядке путей.
- `sig_hash` — по сигнатуре: модификаторы, атрибуты, имя, параметры, возвращаемый тип; для типа — заголовок со списком баз, без членов. Отличает «поменялась сигнатура» от «поменялось тело».
- `iface_hash` файла — по отсортированным парам `(ключ, sig_hash)` его объявлений. Не изменился — зависимые файлы не пересчитываются (раздел 9).

### 3. Метки рёбер и неразрешённые ссылки

У каждого ребра: вид; источник; класс уверенности и число; доказательство (файл, строка, столбец). Ребро, построенное из ссылки, соответствует ровно одному месту в коде (`edges.ref_id`), поэтому у каждого вызова своё доказательство; агрегирование — на стороне запросов.

**Источник** (`edges.source`; метка для агента по ADR-003 в скобках):
- `treesitter` — синтаксический факт + детерминированное правило разрешения (без метки);
- `unity-yaml` — `.meta`, YAML-документы, `.asmdef`, группы Addressables (`unity`);
- `config` — `package.json`, `tsconfig.json`, `go.mod`, `Cargo.toml` (`config`);
- `heuristic` — связь без синтаксического доказательства: строковый литерал, единственное имя в проекте, голое имя в обратных кавычках документа (`heur`);
- `git` — `co_change` (`git`);
- `lsp`, `scip` — уточнение языковым сервером или индексом SCIP (`lsp`, `scip`);
- `model` — локальная модель (ADR-002) (`model`).

**Уверенность.** Класс `EXTRACTED` / `INFERRED` / `AMBIGUOUS` и число 0–1. Разбор и разрешение ставят только `EXTRACTED` и `INFERRED`. `AMBIGUOUS` ставит только модель; неоднозначное при разборе в `edges` не попадает, а уходит в `unresolved` с кандидатами (ADR-001, К3).

| Как найдена цель | Класс | Число |
|---|---|---|
| Тот же файл, лексическая область; явная квалификация; импорт с единственной целью; GUID/fileID из YAML | EXTRACTED | 1.0 |
| Тип получателя из явного объявления (параметр, поле, локальная с типом, `new T()`), расширяющий метод C#, метод трейта через ограничение `T: Trait` | EXTRACTED | 0.95 |
| UnityEvent: единственный метод с именем в иерархии типа; перегрузка выбрана по `m_Mode` | EXTRACTED | 1.0 / 0.9 |
| Тип получателя из возвращаемого типа разрешённого вызова (`var x = Foo.Create()`, `GetComponent<T>()`) | INFERRED | 0.8 |
| Перегрузка выбрана только по числу аргументов из нескольких | INFERRED | 0.8 |
| Go: тип реализует интерфейс по набору методов (имена и число параметров / плюс совпадение типов текстом) | INFERRED | 0.8 / 0.9 |
| Строковый литерал: `SendMessage`, `Invoke`, `StartCoroutine`, `Resources.Load`, `LoadScene`, строковые события TS | INFERRED | 0.7 |
| `.anim` `functionName` при единственном методе с этим именем в классах-наследниках MonoBehaviour | INFERRED | 0.6 |
| Единственное имя в проекте без доказательства импорта (глобальные функции JS, голое имя в документе) | INFERRED | 0.5–0.6 |
| LSP, SCIP | EXTRACTED | 1.0 |

Порог по умолчанию в запросах — 0.5; вызов метода без известного типа получателя ребром не становится (правило Graft: подбор по имени снижал точность с 73% до 37%).

**Неразрешённые ссылки** — таблица `unresolved`, по строке на факт-ссылку, у которой нет ребра. Причины: `ambiguous` (кандидаты — ключами, с числом), `not_found`, `external` (цель вне проекта — `Debug.Log`, `fmt.Println`), `dynamic` (нелитеральный аргумент `Resources.Load(name)`), `unsupported` (известная слепая зона модуля: макросы Rust, `dynamic` в C#). Кандидаты хранятся ключами, а не rowid: удаление кандидата не ломает строку. При каждом обновлении неразрешённые с затронутыми именами разрешаются заново (раздел 9). Запросы показывают их как `ambiguous: N` и `blind spots`, а при `include_ambiguous` — списком кандидатов с меткой `[A]`.

### 4. Хранение: SQLite

Один файл `.codegraph/index.db` в корне проекта, в `.gitignore`, восстанавливаемый; в нём же индекс знаний проекта по [[ADR-007 Хранение знаний и журнала]] — чтобы привязки фактов к узлам проверялись одним запросом (решение лида при принятии ADR). Режим WAL; `foreign_keys=ON` всегда, в том числе при массовой записи; `synchronous=NORMAL`; `busy_timeout=5000`; `journal_size_limit=32 МБ` (как в ue-xray `db.rs:400-420`). Узлы обновляются только `INSERT … ON CONFLICT(key) DO UPDATE` — rowid узла стабилен, пока жив ключ; `INSERT OR REPLACE` запрещён. Факты и рёбра файла — «удалить по `file_id` + вставить». Писатель один: файл-замок `.codegraph/index.lock` плюс `BEGIN IMMEDIATE`; читатели (сервер MCP, хуки) работают параллельно.

```sql
PRAGMA journal_mode = WAL;
PRAGMA foreign_keys = ON;
PRAGMA synchronous = NORMAL;
PRAGMA busy_timeout = 5000;

CREATE TABLE meta(               -- schema_version, key_scheme, hash_scheme, generation, tool_version, root
  k TEXT PRIMARY KEY,
  v TEXT NOT NULL
) STRICT;

CREATE TABLE files(
  id           INTEGER PRIMARY KEY,
  path         TEXT NOT NULL UNIQUE,        -- от корня проекта, '/', регистр с диска
  module       TEXT NOT NULL,               -- csharp | ts | go | rust | unity | markdown | …
  unit         TEXT,                        -- ключ unit, к которому отнесён файл
  size         INTEGER NOT NULL,
  mtime_ns     INTEGER NOT NULL,
  content_hash BLOB NOT NULL,               -- xxh3-128
  module_ver   INTEGER NOT NULL,
  ctx_hash     BLOB NOT NULL,               -- хэш FileCtx (сборка, GUID, путь модуля…)
  iface_hash   BLOB,
  status       INTEGER NOT NULL DEFAULT 0,  -- 0 ok, 1 разобран с ошибками, 2 пропущен (бинарный/большой/не Force Text), 3 сбой модуля
  indexed_at   INTEGER NOT NULL
) STRICT;

CREATE TABLE nodes(
  id         INTEGER PRIMARY KEY,           -- внутренний, наружу не выдаётся
  key        TEXT NOT NULL UNIQUE,
  kind       TEXT NOT NULL,
  layer      INTEGER NOT NULL,
  name       TEXT NOT NULL,                 -- короткое имя для поиска
  qname      TEXT,                          -- полное имя для показа: UOP1.StateMachine.StateMachine.Awake
  parent_id  INTEGER REFERENCES nodes(id) ON DELETE SET NULL,
  file_id    INTEGER REFERENCES files(id) ON DELETE SET NULL,   -- основное место (первое по пути)
  start_line INTEGER, start_col INTEGER, end_line INTEGER, end_col INTEGER,
  sig        TEXT,                          -- сигнатура без тела (L1)
  sig_hash   BLOB,
  body_hash  BLOB,
  flags      INTEGER NOT NULL DEFAULT 0,
  props      TEXT                           -- JSON: asset_type, path объекта, components, entry, address…
) STRICT;
CREATE INDEX nodes_name   ON nodes(name);
CREATE INDEX nodes_parent ON nodes(parent_id);
CREATE INDEX nodes_file   ON nodes(file_id);
CREATE INDEX nodes_kind   ON nodes(kind, layer);

CREATE TABLE decls(               -- все места объявления: partial, #if-ветки, namespace/пакет в нескольких файлах
  node_id    INTEGER NOT NULL REFERENCES nodes(id) ON DELETE CASCADE,
  file_id    INTEGER NOT NULL REFERENCES files(id) ON DELETE CASCADE,
  start_line INTEGER NOT NULL, start_col INTEGER NOT NULL,
  end_line   INTEGER NOT NULL, end_col INTEGER NOT NULL,
  body_hash  BLOB,
  PRIMARY KEY(file_id, node_id, start_line, start_col)
) STRICT, WITHOUT ROWID;
CREATE INDEX decls_node ON decls(node_id);

CREATE TABLE refs(                -- факты-ссылки: всё, что разрешается; одна строка = одно место в файле
  id      INTEGER PRIMARY KEY,
  file_id INTEGER NOT NULL REFERENCES files(id) ON DELETE CASCADE,
  src_id  INTEGER NOT NULL REFERENCES nodes(id) ON DELETE CASCADE,   -- объемлющее объявление
  kind    TEXT NOT NULL,          -- RefKind: call, type_use, inherit, import, member_access, script_guid, method_by_name, …
  name    TEXT NOT NULL,          -- искомое имя как записано (последний сегмент), GUID, путь, имя поля
  ctx     TEXT,                   -- JSON: квалификатор/тип получателя, арность, область, аргументы дженериков, подсказки
  line    INTEGER NOT NULL,
  col     INTEGER NOT NULL
) STRICT;
CREATE INDEX refs_name ON refs(name);          -- обратный индекс имён
CREATE INDEX refs_file ON refs(file_id);
CREATE INDEX refs_src  ON refs(src_id);

CREATE TABLE ref_deps(            -- на какие узлы опиралось разрешение ссылки (типы получателя, базы, импорты)
  node_id INTEGER NOT NULL REFERENCES nodes(id) ON DELETE CASCADE,
  ref_id  INTEGER NOT NULL REFERENCES refs(id)  ON DELETE CASCADE,
  PRIMARY KEY(node_id, ref_id)
) STRICT, WITHOUT ROWID;
CREATE INDEX ref_deps_ref ON ref_deps(ref_id);

CREATE TABLE edges(
  id             INTEGER PRIMARY KEY,
  src_id         INTEGER NOT NULL REFERENCES nodes(id) ON DELETE CASCADE,
  dst_id         INTEGER NOT NULL REFERENCES nodes(id) ON DELETE CASCADE,
  kind           TEXT NOT NULL,
  source         TEXT NOT NULL,                  -- treesitter | unity-yaml | config | heuristic | git | lsp | scip | model
  conf_class     INTEGER NOT NULL,               -- 0 EXTRACTED, 1 INFERRED, 2 AMBIGUOUS (только model)
  conf           REAL NOT NULL,
  ref_id         INTEGER UNIQUE REFERENCES refs(id) ON DELETE CASCADE,  -- NULL у локальных и производных рёбер
  origin_file_id INTEGER REFERENCES files(id) ON DELETE CASCADE,        -- чьи факты породили ребро
  line           INTEGER,                        -- доказательство: строка и столбец в origin_file
  col            INTEGER,
  props          TEXT
) STRICT;
CREATE INDEX edges_dst    ON edges(dst_id, kind);
CREATE INDEX edges_src    ON edges(src_id, kind);
CREATE INDEX edges_origin ON edges(origin_file_id);

CREATE TABLE unresolved(
  ref_id     INTEGER PRIMARY KEY REFERENCES refs(id) ON DELETE CASCADE,
  reason     TEXT NOT NULL,     -- ambiguous | not_found | external | dynamic | unsupported
  candidates TEXT,              -- JSON [{"key":"cs:…","score":0.5}] — ключи, не rowid
  attempts   INTEGER NOT NULL DEFAULT 1
) STRICT;
CREATE INDEX unresolved_reason ON unresolved(reason);

CREATE TABLE fact_cache(          -- FileFacts целиком (postcard + zstd): области и импорты для повторного разрешения, быстрый возврат при git checkout
  content_hash BLOB NOT NULL,
  module       TEXT NOT NULL,
  module_ver   INTEGER NOT NULL,
  ctx_hash     BLOB NOT NULL,
  facts        BLOB NOT NULL,
  last_used    INTEGER NOT NULL,
  PRIMARY KEY(content_hash, module, module_ver, ctx_hash)
) STRICT, WITHOUT ROWID;

CREATE VIRTUAL TABLE nodes_fts USING fts5(   -- rowid = nodes.id; ведётся кодом записи в той же транзакции
  name,      -- как есть
  words,     -- name, разрезанное по camelCase/snake_case, в нижнем регистре: "player controller"
  qname,
  path,
  text,      -- doc-комментарий, заголовок и текст раздела документа
  content = '', contentless_delete = 1,
  tokenize = "unicode61 remove_diacritics 2 tokenchars '_'"
);
```

Инварианты (проверяются тестом и командой `codegraph doctor`): у каждой строки `refs` после разрешения ровно одно из «ребро с этим `ref_id`» или «строка `unresolved`»; у каждого не-`external` узла есть хотя бы одна строка `decls`; `external`-узел без входящих рёбер удаляется.

**Размер базы** (оценка, проверить — Г3): на 100 тыс. строк кода ≈ 25 тыс. узлов, 80–100 тыс. ссылок, столько же рёбер, 20–40 тыс. `ref_deps`; вместе с индексами, FTS и `fact_cache` — 30–60 МБ. Chop Chop с ассетами (по оценке 30–60 тыс. узлов Unity) — ещё 20–40 МБ. Сжатие после полной индексации — `wal_checkpoint(TRUNCATE)` и `VACUUM` при доле свободных страниц > 25% (ue-xray `compact_after_import`).

**Кэш смежности** в процессе `codegraph mcp`: при первом запросе и при изменении `meta.generation` (проверка через `PRAGMA data_version` перед запросом) грузятся `edges(src_id, dst_id, kind, conf)` и `nodes(id, parent_id, kind, flags)` в две CSR-структуры (прямую и обратную): `offs: Vec<u32>`, `dst: Vec<u32>`, `kind: Vec<u8>`, `conf: Vec<u8>` (0–100). 200 тыс. рёбер — ≈ 5 МБ и ≈ 50 мс на загрузку. Обходы (`refs` с глубиной, `impact`, where-used) идут по нему; рекурсивный CTE — путь для CLI без кэша и эталон для тестов.

### 6. Трейт модуля языка и формата

Модуль — две части: **извлечение** (чистая функция `(файл, контекст) → факты`, параллельно, кэшируется) и **разрешение** (правила языка поверх общего индекса символов). Конфиги модуля (`.asmdef`, `tsconfig.json`, `go.mod`, `Cargo.toml`, `.meta`) читаются раньше, на шаге раскладки, и дают контекст файлам.

```rust
// codegraph-core

pub struct Key(pub Box<str>);                       // стабильный внешний адрес узла
pub type Hash128 = [u8; 16];
pub struct Pos { pub line: u32, pub col: u32 }      // 1-based; col — байты UTF-8 строки
pub struct Span { pub start: Pos, pub end: Pos }

pub enum Claim { Source, Config, Skip }

pub struct SourceFile<'a> {
    pub path: &'a str,               // от корня, '/'
    pub text: &'a str,               // UTF-8 без BOM (не-UTF-8 — с заменой, в diags)
    pub content_hash: Hash128,
}

pub struct FileCtx {                 // из раскладки; входит в ключ кэша через ctx_hash
    pub unit: Option<Key>,           // сборка C#, пакет npm, путь импорта Go, крейт Rust
    pub module_path: Option<String>, // Rust: "graphics::canvas"; TS: путь от корня пакета
    pub unity_guid: Option<String>,  // GUID ассета из соседнего .meta
    pub is_test_path: bool,
    pub opts: serde_json::Value,     // версия языка, define-символы asmdef и т. п.
}

pub struct FileFacts {
    pub decls:   Vec<Decl>,
    pub refs:    Vec<RefFact>,
    pub imports: Vec<ImportFact>,
    pub scopes:  Vec<ScopeFact>,
    pub edges:   Vec<LocalEdge>,     // связи, доказанные внутри файла (объекты YAML того же файла, заголовки)
    pub units:   Vec<UnitDecl>,      // только для конфигов
    pub diags:   Vec<Diag>,          // ошибки разбора, пропущенные участки, слепые зоны
}

pub struct Decl {
    pub key: Key, pub kind: NodeKind, pub name: String, pub qname: String,
    pub parent: Option<Key>, pub span: Span,
    pub sig: Option<String>, pub sig_hash: Hash128, pub body_hash: Hash128,
    pub flags: NodeFlags, pub props: Option<serde_json::Value>,
}

pub struct RefFact {
    pub from: Key,                   // объемлющее объявление
    pub kind: RefKind,
    pub name: String,                // как написано: "Bar", GUID, путь, имя метода/поля
    pub ctx: RefCtx,
    pub at: Pos,
}

pub struct RefCtx {
    pub qualifier: Qualifier,
    pub arity: Option<u8>,           // число аргументов вызова
    pub type_args: Vec<TypeRef>,     // GetComponent<T>, new List<T>
    pub scope: ScopeId,              // для лексического поиска и using
    pub hint: Option<String>,        // m_Mode UnityEvent, имя события, строковый канал
}

pub enum Qualifier {
    None,                            // простое имя — лексический поиск
    This, Base,
    Path(Vec<String>),               // A.B.C — пространство имён, тип или модуль; решает резолвер
    Typed(TypeRef),                  // тип получателя известен в файле: параметр, поле или локальная с типом, new T()
    Member(String),                  // поле/свойство текущего типа — его тип найдёт резолвер
    ReturnOf(Box<RefFact>),          // x = Foo.Create(); x.M() — тип = возвращаемый тип цели вложенной ссылки
    Unknown,                         // тип получателя не вывести — ребра не будет (unresolved)
}

pub struct TypeRef { pub name: String, pub args: Vec<TypeRef>, pub array: u8, pub nullable: bool }

pub trait LanguageModule: Send + Sync + 'static {
    fn id(&self) -> &'static str;                        // "csharp"
    fn version(&self) -> u32;                            // любое изменение извлечения → +1 → сброс кэша фактов
    fn claims(&self, path: &str) -> Claim;
    fn layout(&self, cfg: &SourceFile) -> Vec<UnitDecl> { Vec::new() }
    fn file_ctx(&self, path: &str, layout: &Layout) -> FileCtx;
    fn extract(&self, file: &SourceFile, ctx: &FileCtx) -> FileFacts;   // без IO, без глобального состояния, не паникует
    fn resolver(&self) -> Option<&dyn Resolver> { None }
}

pub enum Phase { Types, Code, CrossLayer }             // порядок: базы типов → ссылки кода → Unity, документы, память

pub trait Resolver: Send + Sync {
    fn phase(&self, kind: RefKind) -> Phase;
    /// Производные рёбра по затронутым типам: overrides, implements по набору методов (Go), entry-флаги.
    fn type_pass(&self, idx: &dyn SymbolIndex, types: &[Key], out: &mut Vec<DerivedEdge>);
    /// Разрешение одной ссылки; только чтение индекса — вызывается параллельно.
    fn resolve(&self, idx: &dyn SymbolIndex, r: &StoredRef) -> Resolution;
}

pub enum Resolution {
    Resolved   { target: Key, kind: EdgeKind, source: Source, conf: Confidence, deps: SmallVec<[Key; 4]> },
    Ambiguous  { candidates: Vec<(Key, f32)>, deps: SmallVec<[Key; 4]> },
    Unresolved { reason: UnresolvedReason, deps: SmallVec<[Key; 4]> },
}

pub trait SymbolIndex: Sync {                           // MemSymbolIndex (полная загрузка) и SqlSymbolIndex (ленивый, для хука)
    fn get(&self, key: &str) -> Option<DeclInfo>;
    fn children(&self, parent: &str, name: &str) -> SmallVec<[DeclInfo; 2]>;
    fn by_name(&self, scheme: &str, name: &str) -> Vec<DeclInfo>;
    fn by_qname(&self, unit: &str, qname: &str) -> Option<DeclInfo>;
    fn bases(&self, ty: &str) -> SmallVec<[Key; 2]>;          // после фазы Types
    fn file_scope(&self, file: &str, scope: ScopeId) -> ScopeView<'_>;   // using/import из fact_cache
    fn unit(&self, key: &str) -> Option<&UnitDecl>;
    fn by_guid(&self, guid: &str) -> Option<AssetInfo>;       // Unity: guid → путь, импортёр
}
```

Требования к модулю: извлечение детерминировано (одинаковый вход — байт-в-байт одинаковые факты, в том числе порядок); ошибки синтаксиса не прерывают разбор (tree-sitter восстанавливается, участок с `ERROR` — в `diags`); модуль не читает другие файлы — всё межфайловое делает разрешение. Парсер tree-sitter не `Sync`: конвейер держит по парсеру на поток (`rayon::map_init`).

### 8. Разрешение связей

#### 8.1. Общий порядок

1. **Индекс символов.** Все объявления: ключ → вид, имя, родитель, сигнатура, флаги; индексы по короткому имени, по `(unit, qname)`, по родителю и имени, по GUID.
2. **Фаза `Types`.** Ссылки вида `inherit`/`implement` → рёбра `inherits`/`implements`; карта баз `bases(T)`. Затем `type_pass` по затронутым типам: `overrides` (метод с тем же именем и числом параметров в базах и интерфейсах; явная реализация C# — по имени интерфейса), неявные интерфейсы Go, флаги `entry`. Производные рёбра хранятся с `origin_file_id` = файл объявления типа-наследника.
3. **Фаза `Code`.** Импорты → карта импорта файла; затем остальные ссылки кода: лексическая область → импорты → единица → видимые единицы; член — по типу получателя с подъёмом по `bases`.
4. **Фаза `CrossLayer`.** Скрипты и UnityEvent (нужны классы и методы), сериализованные поля (нужны иерархии), упоминания в документах (нужен весь код), якоря памяти.
5. **Итог по каждой ссылке.** Одна цель → ребро. Несколько → `unresolved(ambiguous)` с кандидатами. Ноль → `unresolved(not_found | external | dynamic | unsupported)`. Всегда — `deps`: узлы, через которые шло разрешение (тип получателя, его базы, поле с типом, алиас, цель вложенной `ReturnOf`); они пишутся в `ref_deps` для инкремента.
6. **Внешние символы.** Заглушка `external` создаётся только для внешних типов в списках баз и `uses_type`, если имя есть в таблице известных типов модуля (`MonoBehaviour`, `ScriptableObject`, `StateMachineBehaviour`, `Editor`, `EditorWindow`, `UnityEvent`…) и в файле есть соответствующий `using`. Вызовы внешних членов (`Debug.Log`) — `unresolved(external)` без кандидатов, в `blind spots` не попадают.
7. **Связи между языками** не строятся (C# ↔ TS и т. п.) — это [[F-12 Связи между языками]].

#### 8.2. C# (подробно)

**Область видимости сборок.** Сборка видит свои типы и типы сборок из `references` своего `.asmdef` (по имени или `GUID:`), с учётом `autoReferenced`. `Assembly-CSharp` видит все сборки с `autoReferenced: true`; сборки `.asmdef` не видят `Assembly-CSharp`; `…-Editor` видит всё то же плюс редакторные; `…-firstpass` компилируется раньше и видна обоим. Для проектов без Unity — `ProjectReference` из `.csproj`.

**Имя типа (простое `Foo`) в области `s`** — первое найденное по шагам, по упрощённым правилам спецификации C#:
1. параметры-типы объемлющих метода и типа;
2. вложенные типы объемлющих типов, изнутри наружу, и их базовых типов;
3. для каждого объемлющего пространства имён от внутреннего к глобальному (`A.B.C` → `A.B.C`, `A.B`, `A`, глобальное): типы этого пространства в видимых сборках; затем алиасы `using X = …` этого блока; затем типы из `using`-директив этого блока;
4. `global using` сборки;
5. `using static T` — вложенные типы `T`.

На шаге найдено больше одного — `ambiguous` (в компиляторе это ошибка CS0104; у нас — кандидаты). Квалифицированное `A.B.Foo`: первый сегмент — алиас, пространство имён или тип по тем же шагам; `global::` — от корня. Дженерик — по имени и арности (`List<T>` ищет ``List`1``).

**Базы.** Список баз `class A : B, IC` → первый класс — `inherits`, интерфейсы — `implements` (у интерфейса все базы — `implements`). `partial`: базы собираются со всех объявлений.

**Член `recv.M(args)`.** Тип получателя по `Qualifier`:
- `None` — сначала локальные функции и члены текущего типа и его баз (неявный `this`), затем `using static`, затем поиск типа (статический вызов без квалификации невозможен — только `this`);
- `This` → текущий тип; `Base` → первая база;
- `Path(["Foo"])` → если `Foo` — тип, то статический член; если пространство имён — продолжить путь;
- `Typed(T)` → `T` из объявления параметра, поля, свойства, локальной с явным типом, `new T()`, `var x = new T()`, `foreach (T x …)`, `as T`, `is T x`, `out T x`, `catch (T e)`;
- `Member(f)` → тип поля или свойства `f` текущего типа или баз (`deps` += поле);
- `ReturnOf(r)` → возвращаемый тип цели `r` (рекурсивно, глубина ≤ 4); `GetComponent<T>`, `GetComponentInChildren<T>`, `FindObjectOfType<T>`, `AddComponent<T>`, `Instantiate(T)` → `T` из таблицы известных дженерик-фабрик; `INFERRED 0.8`;
- параметр-тип `T` с ограничением `where T : Foo` → `Foo`;
- иначе `Unknown` → `unresolved(not_found)`, без угадывания по имени.

Поиск члена `M` в типе `T`: сам тип (все `partial`) → цепочка `bases` классов → интерфейсы (для получателя-интерфейса). Не найден — **расширяющие методы**: статические классы в видимых пространствах имён (по `using` области) с методом `M`, у которого первый параметр `this X`, где `X` — `T` или его база (`EXTRACTED 0.95`). **Перегрузки**: фильтр по числу аргументов с учётом необязательных и `params`; осталось больше одной — по типам литералов; всё ещё больше одной — `INFERRED 0.8` на единственную по арности, иначе `ambiguous` среди перегрузок.

**Виртуальная диспетчеризация.** Вызов `b.M()` с `b: Base` даёт ребро на `Base.M` (`EXTRACTED`); связь с переопределениями — через `overrides` (раздел 10, обход с учётом диспетчеризации).

**События и делегаты.** `E += H` / `E -= H` / `E.AddListener(H)` → `handles` H → E и `references` S → H (S — метод с подпиской); `E?.Invoke(…)`, `E(…)` для поля-события или делегата → `raises` S → E. Лямбда-обработчик: вызовы внутри неё — рёбра объемлющего метода; `handles` не строится.

**Атрибуты и прочее.** `[RequireComponent(typeof(T))]` → `uses_type` (`props.via=require_component`); `[CustomEditor(typeof(T))]` → `uses_type` + `entry=unity_editor`; `[MenuItem]`, `[InitializeOnLoad]`, `[RuntimeInitializeOnLoadMethod]` → `entry=unity_editor`; `[Test]`, `[UnityTest]`, `[TestCase]` → флаг `test`; `nameof(M)` → `references`; `typeof(T)` → `uses_type`.

**Строковые вызовы Unity.** `SendMessage("M")`, `BroadcastMessage`, `Invoke("M", t)`, `InvokeRepeating`, `StartCoroutine("M")` с литералом → `calls` на метод `M` в иерархии текущего типа, `heuristic`, `INFERRED 0.7`; не литерал → `unresolved(dynamic)`. `Resources.Load("p")` → ассеты `**/Resources/p.*`; `Addressables.LoadAssetAsync("addr")` → ассет с `props.address = addr`; `SceneManager.LoadScene("Name"|i)` → сцена из `EditorBuildSettings` по имени или индексу — все `unity_ref`, `heuristic`, `INFERRED 0.7–0.8`.

**Сообщения движка.** В `type_pass`: метод класса, унаследованного (транзитивно, через заглушки) от `MonoBehaviour`, `ScriptableObject`, `StateMachineBehaviour`, `Editor`, `EditorWindow`, с именем из списка сообщений (`Awake`, `Start`, `Update`, `FixedUpdate`, `LateUpdate`, `OnEnable`, `OnDisable`, `OnDestroy`, `OnTrigger*`, `OnCollision*`, `OnMouse*`, `OnValidate`, `OnGUI`, `OnApplicationPause`…) → флаг `entry`, `props.entry=unity_message`.

**Известные ограничения C#** (в `diags` и `blind spots`): `dynamic`, рефлексия, `#if`-ветки не вычисляются (обе ветки — объявления одного узла), вывод типа из лямбд и LINQ-цепочек не делается (`Unknown`), DLL-скрипты (`m_Script` с GUID DLL) — `unresolved(unsupported)`.

#### 8.3. TS/JS

- **Модули.** Относительные пути; `tsconfig` `paths`, `baseUrl`, `extends`; `package.json` `exports`/`imports` и workspaces; `.js` → `.ts`/`.tsx`; `index.*`; динамический `import("литерал")` → `imports`.
- **Экспорты.** Таблица экспорта модуля с реэкспортами (`export * from`, `export { a as b } from`) — неподвижная точка по графу реэкспортов, защита от циклов.
- **Имена.** Лексическая область (блок → функция → модуль) → импорты (именованный, по умолчанию, пространство имён `* as ns` → `ns.x` как путь) → глобальные объявления пакета (`declare global`, скрипты без модулей) → `unresolved`.
- **Члены.** `this.m()` в классе → класс и цепочка `extends`; получатель с аннотацией типа, `new T()`, возврат разрешённой функции с аннотацией → тип; иначе `unresolved`, без подбора по имени. `implements` — ребро на интерфейс; `overrides` — по имени метода в базе.
- **Строковые события.** `emitter.on("evt", h)` / `emit("evt")` с литералами → `handles`/`raises` на синтетическое имя канала — после MVP, по итогам [[F02-03 Тестовые кодовые базы с ожидаемым графом]].

#### 8.4. Go

- Пакет — папка; путь импорта — модуль из `go.mod` + относительная папка; `replace` учитывается; экспорт — заглавная буква.
- Имена: область функции → пакет (все файлы пакета) → импорты (с алиасом, `.`-импорт).
- Методы: получатель из `var x T`, `x := T{}`, `x := &T{}`, `x := NewT()` (возвращаемый тип), параметров и получателя метода; `(*T)` и `T` — один набор для поиска. Встраивание: поиск по уровням встраивания (продвинутые методы), ребро `inherits` с `props.embed`.
- Неявные интерфейсы в `type_pass`: для интерфейса `I` и конкретного типа `T` проекта — если набор методов `T` покрывает `I` по именам и числу параметров → `implements` `INFERRED 0.8` (0.9 при текстовом совпадении типов), методы → `overrides`. Вызов через значение интерфейса → ребро на метод интерфейса.
- `go f()` → `calls` с `props.async`; каналы — не рёбра.

#### 8.5. Rust

- Крейт — цель сборки из `Cargo.toml` (lib — имя пакета с `-` → `_`, bin, examples); модули по путям файлов и встроенным `mod x {}`; `#[path]` не поддерживается (`diags`).
- `use`-деревья: `crate::`, `self::`, `super::`, переименование `as`, glob `*` (glob даёт кандидатов с меньшим приоритетом, чем явные имена).
- `impl T` → методы — дети типа по разрешённому `T`; `impl Tr for T` → `implements` T → Tr, методы → `overrides`.
- Методы `x.m()`: тип из `let x: T`, `let x = T::new()` (возврат `Self` → `T`), `self` в `impl`, параметров; поиск: inherent-методы `T` → методы трейтов, реализованных для `T` в проекте (больше одного — `ambiguous`); `dyn Tr`/`impl Tr`/`T: Tr` → метод трейта `EXTRACTED 0.95`.
- Макросы: вызов `m!()` → `calls` на узел `macro`; содержимое макросов не раскрывается — `unsupported` для ссылок внутри, пометка в `blind spots`.

#### 8.6. Unity

**Извлечение** (модуль `unity`, потоковый построчный разбор, fileID — строки):
- `.meta` → узел `asset` `u:<guid>` (объявление в `.meta`-файле; `props.importer`, `props.asset_type`, путь ассета).
- `.unity`, `.prefab`, `.asset`, `.controller`, `.anim`, `.overrideController` — деление на документы по `^--- !u!(\d+) &(-?\d+)( stripped)?`; из тела читаются только нужные ключи с учётом отступа: `m_Script`, `m_GameObject`, `m_Name`, `m_Father`/`m_Children` (путь объекта), `m_SourcePrefab`, `m_TransformParent`, `m_RemovedComponents`, `m_AddedComponents`, `m_Modifications[].target/propertyPath/objectReference`, `m_CorrespondingSourceObject`, `m_PrefabInstance`, `m_PersistentCalls.m_Calls[]` (`m_Target`, `m_TargetAssemblyTypeName`, `m_MethodName`, `m_Mode`), любые `{fileID: …, guid: …}`, `m_AssetGUID`, `references.RefIds[].type`, `m_Events[].functionName`.
- Сериализованные поля компонента — ключи верхнего уровня документа MonoBehaviour, кроме служебных (`m_ObjectHideFlags`, `m_CorrespondingSourceObject`, `m_PrefabInstance`, `m_PrefabAsset`, `m_GameObject`, `m_Enabled`, `m_EditorHideFlags`, `m_Script`, `m_Name`, `m_EditorClassIdentifier`); пользовательские поля с префиксом `m_` сохраняются.
- Заглушки `stripped` — не узлы: факт-алиас «локальный fileID → (guid, fileID) источника через экземпляр». Добавленный в экземпляр компонент — ребёнок узла `prefab_instance` с `props.on_object` = ключ объекта-источника. Удалённые — `props.removed` у `prefab_instance` (пары `guid:fileID` строками) и ссылка `removes_component`.
- Локальные рёбра файла (ссылки `{fileID}` без `guid`) — `unity_ref` сразу при извлечении.

**Разрешение:**
1. `m_Script` → GUID → ассет-скрипт → файл `.cs` → класс с именем файла (правило Unity) → `runs_script` `EXTRACTED 1.0`; класса с таким именем нет, но в файле один наследник MonoBehaviour/ScriptableObject → `INFERRED 0.8`; GUID — DLL или неизвестен → `unresolved(unsupported | not_found)` («Missing Script»).
2. `m_SourcePrefab` → `instance_of`; корневой PrefabInstance без родителя в `.prefab` → `variant_of` на уровне ассетов.
3. UnityEvent: тип цели — из `m_TargetAssemblyTypeName` (``Ns.Type, Assembly`` → `cs:<Assembly>:Ns.Type`), при отсутствии — `m_Target` → компонент → `runs_script`; метод `m_MethodName` в типе и базах; перегрузка по `m_Mode` (1 без аргументов, 2 Object, 3 int, 4 float, 5 string, 6 bool); цель — GameObject или встроенный компонент (`SetActive`) → `unresolved(external)`. Ребро `unity_event` от владельца события.
4. Поля: для компонента с классом `C` каждый ключ-поле → поле `C` или его баз → `serializes` asset → поле (одно ребро на пару ассет–поле, `props.count`); не найдено → `unresolved(not_found)` (признак переименования без `[FormerlySerializedAs]`).
5. `{guid}`, `m_AssetGUID`, `objectReference` → `unity_ref` на ассет или на объект (`u:<guid>:<fileID>`, если такой узел есть, иначе на ассет с `props.file_id`); встроенные ресурсы (`0000000000000000e000000000000000` и подобные) — не рёбра.
6. `[SerializeReference]` `{class, ns, asm}` → `references_type` на `cs:<asm>:<ns>.<class>`.
7. `.anim` `functionName` → методы с этим именем в наследниках MonoBehaviour: один → `anim_event` `INFERRED 0.6`, несколько → `ambiguous`.

**Где висит компонент (where-used)** — в запросе, а не материализованной таблицей (раздел 10.3): от класса к компонентам по `runs_script`, затем вверх по цепочкам `instance_of` с учётом удалённых компонентов.

#### 8.7. Markdown

Документ → разделы по дереву заголовков (`contains` через `parent_id`); frontmatter — в `props`. Ссылки `[..](путь)`, `[[вики]]`, пути в тексте → `links_to` на документ, раздел или `file:` (только существующие — узлы не выдумываются). Имена в обратных кавычках → `mentions`: форма с путём или полным именем (`Player.Jump`, `Assets/…/Player.cs`) → `EXTRACTED 0.9`; голое имя с единственным совпадением → `INFERRED 0.6`, `heuristic`; несколько → `ambiguous`. Документы — узлы того же графа: `impact` метода показывает разделы, которые его упоминают.

### 9. Инкрементальное обновление

**Пакет обновления** — множество изменённых файлов `U` (из хука, отпечатка или `--paths`). В одной транзакции:

1. Для каждого `f ∈ U` — новые факты (кэш или извлечение). Для удалённых — пустые факты.
2. **Сравнение объявлений** старых и новых по ключу: добавленные `A`, удалённые `R`, со сменой сигнатуры `S` (`sig_hash`), только тело `B`. Если `iface_hash` файла не изменился — `A = R = S = ∅`.
3. **Множество ссылок на повторное разрешение `I`** (собирается до удалений):
   - все ссылки файлов `U` (они вставляются заново);
   - ссылки с ребром на узлы `R ∪ S` (`edges.dst_id` при `ref_id IS NOT NULL`);
   - ссылки с зависимостью от `R ∪ S` (`ref_deps.node_id`) — цепочки через тип получателя, поле, базу, алиас;
   - ссылки с `name` из коротких имён `A ∪ R ∪ S` — по индексу `refs_name`: новое объявление может закрыть неразрешённую ссылку или затенить старую цель, удаление — сделать неоднозначную однозначной;
   - для типов из `S` со сменой списка баз — ещё и ссылки, чьи `ref_deps` содержат наследников этих типов (обход `inherits` вниз).
4. **Запись фактов:** удалить `refs`, локальные рёбра и `decls` файлов `U` (каскадом уходят их рёбра, `unresolved`, `ref_deps`); upsert узлов из новых `decls` (rowid живых ключей не меняется); вставить `decls`, `refs`, локальные рёбра; удалить узлы без `decls` (не `external`) — каскадом уходят входящие рёбра, которые уже в `I`.
5. **`type_pass`** для затронутых типов: типы из файлов `U`, типы из `S`, их наследники; их производные рёбра (`overrides`, неявные `implements`, флаги `entry`) удаляются и строятся заново.
6. **Разрешение `I`** по фазам, параллельно; запись рёбер, `unresolved`, `ref_deps`.
7. FTS — удалить и вставить строки изменённых и удалённых узлов.
8. `meta.generation += 1`; `COMMIT`.

**Что инвалидируется при каком изменении**

| Изменение | Переизвлечение | Повторное разрешение |
|---|---|---|
| Тело метода (частый случай правки) | файл | только ссылки файла; `body_hash` → статус якорей памяти |
| Сигнатура, добавление или удаление члена | файл | ссылки файла + ссылки на эти узлы и через них (`ref_deps`) + ссылки с теми же короткими именами |
| Список баз типа | файл | то же + наследники типа (`type_pass` и их ссылки) |
| Файл удалён | — | ссылки на его узлы → `unresolved` или новая цель |
| Файл переименован (тот же `content_hash`) | нет, если `ctx` тот же (C#: ключи не меняются, меняются `decls`) | TS/Rust/Go: как удаление + добавление; якоря памяти — «переехал» |
| `.asmdef`, `.csproj`, `tsconfig.json`, `package.json`, `go.mod`, `Cargo.toml` | все файлы единицы (сменился `ctx_hash`) | все ссылки языка (полное разрешение языка, без повторного разбора других единиц) |
| `.meta` (GUID, путь) | `.meta` и файл ассета (его `unity_guid` в `ctx`) | ссылки с `name` = этот GUID |
| YAML ассета | файл | ссылки файла; where-used не материализован — ничего больше |
| Смена `version()` модуля | все файлы модуля (кэш не совпадёт) | все ссылки языка |
| Смена `HEAD` | — | `co_change` в фоне |

**Проверка корректности:** тест `testkit` «инкремент = полная сборка» — на каждой фикстуре сценарий правок (добавить/удалить метод, переименовать класс, сменить базу, перенести файл, поменять `.asmdef`, удалить компонент из префаба), после каждой правки экспорт графа после инкремента совпадает с экспортом после `index --full` (Г9).

#### 10.2. `impact`

**Вход → стартовые узлы.** `Symbols` — узлы по `resolve_target`. `Files` — все объявления файлов. `Diff` — изменённые строки `git diff` (рабочая копия, индекс или диапазон) → самый внутренний `decl`, содержащий строку; вид изменения — по сравнению `sig_hash`/`body_hash` старой версии (из графа до обновления) и новой: `signature`, `body`, `removed`, `renamed` (удалён + добавлен с равным `body_hash`), `serialized_field` (поле с `[SerializeField]` или `public` в наследнике MonoBehaviour).

**Алгоритм (кэш смежности, BFS по уровням):**
1. `seed` = стартовые узлы + их потомки по `parent_id` (для типа — все члены).
2. `disp` = `seed` + замыкание вверх по `overrides` (базовые и интерфейсные методы): вызов `Base.M()` может прийти в переопределение.
3. Обход входящих рёбер видов зависимости (все, кроме `contains`, `imports`, `co_change`) от `disp`, глубина ≤ `depth`; уверенность пути — произведение `conf`, отсечение по `min_conf`. На первом шаге от узлов `disp \ seed` не идём по входящим `overrides` (соседние переопределения не зависят от нашего метода).
4. Через события: для обработчика `H` — `raises` события `E`, если есть `handles H → E` (косвенные вызывающие, помечаются `via event`).
5. Unity: для стартовых классов и их полей и методов — `where_used` (размещения, ассеты с данными поля, UnityEvent) на той же глубине 1.
6. Группировка: глубина 1 — «сломается», 2 — «вероятно затронет», 3 — «может затронуть»; тесты — узлы с флагом `test` среди найденных и тестовые файлы по пути: `changed` (тронуты в diff), `stale` (есть, не тронуты), `none`; `co_change` файлов старта; риск по признакам (`exported`, `entry=unity_message`, UnityEvent, сериализованное поле, число вызывающих из других единиц, нет тестов); `blind_spots`; привязанные записи памяти со статусом.

**Тот же обход рекурсивным SQL** (CLI без кэша; эталон для тестов; без шагов 4–6, Unity-обход через префабы упрощён: подъём от объекта Unity к ассету без увеличения глубины и `instance_of` без учёта удалённых компонентов — точный ответ даёт `where_used`):

```sql
-- :key — ключ узла; :depth — 2; :min_conf — 0.5; :limit — 500
WITH RECURSIVE
seed(id) AS (
  SELECT id FROM nodes WHERE key = :key
  UNION
  SELECT n.id FROM nodes n JOIN seed s ON n.parent_id = s.id
),
disp(id) AS (
  SELECT id FROM seed
  UNION
  SELECT e.dst_id FROM edges e JOIN disp d ON e.src_id = d.id WHERE e.kind = 'overrides'
),
walk(id, depth, conf) AS (
  SELECT id, 0, 1.0 FROM disp
  UNION
  SELECT e.src_id, w.depth + 1, w.conf * e.conf
  FROM walk w JOIN edges e ON e.dst_id = w.id
  WHERE w.depth < :depth
    AND w.conf * e.conf >= :min_conf
    AND e.kind NOT IN ('imports', 'co_change')
    AND NOT (e.kind = 'overrides' AND w.depth = 0 AND w.id NOT IN (SELECT id FROM seed))
  UNION
  SELECT n.parent_id, w.depth, w.conf                 -- объект Unity → его ассет без роста глубины
  FROM walk w JOIN nodes n ON n.id = w.id
  WHERE n.layer = 2 AND n.kind <> 'asset' AND n.parent_id IS NOT NULL
)
SELECT n.key, n.kind, n.qname, f.path, n.start_line,
       MIN(w.depth) AS depth, MAX(w.conf) AS conf
FROM walk w
JOIN nodes n ON n.id = w.id
LEFT JOIN files f ON f.id = n.file_id
WHERE w.id NOT IN (SELECT id FROM disp)
GROUP BY w.id
ORDER BY depth, conf DESC, n.qname
LIMIT :limit;
```

Имена и пути берутся тем же запросом (у ue-xray был N+1 запрос имени на строку, `impact.rs:210-265`). Защита от циклов — `UNION` (одинаковые `(id, depth, conf)` не повторяются) и предел глубины; флаг `truncated`, если `LIMIT` достигнут.

Для поля `F`: ассеты с `serializes → F` (+ совет `[FormerlySerializedAs]` в `impact` при переименовании). Для метода `M`: входящие `unity_event`, `anim_event`, строковые `calls` (`heuristic`). ### 12. Тестирование модулей

Базы — [[F02-03 Тестовые кодовые базы с ожидаемым графом]]: `Tests/fixtures/<lang>/<case>/` (`csharp`, `unity`, `ts`, `go`, `rust`, `markdown`), рядом — файл ожидаемого графа в формате `Bench/README.md` ([[F02-01 Эталонные связи в наших проектах]]).

Три уровня проверок:
1. **Снимки фактов** (`cargo test -p codegraph-csharp` и т. д.): для каждого файла фикстуры — `FileFacts` в каноническом текстовом виде, сравнение со снимком (`insta`). Ловит регрессии извлечения и нестабильность ключей.
2. **Граф против ожидаемого** (`cargo test -p codegraph-testkit`): индексация базы → `codegraph export --format edges` (строки `вид ключ_от -> ключ_к класс число`, сортированные) → адаптер `to_bench()` переводит ключи и виды в нотацию `Bench/README.md` → сравнение: обязательные связи (полнота), запрещённые связи-ловушки (точность), допустимые пропуски; отчёт «недостающие / лишние»; пороги — в `Tests/fixtures/<lang>/thresholds.toml`. Тот же раннер с адаптером для CBM и `colbymchenry/codegraph` — [[F02-02 Скрипт прогона набора проверок]].
3. **Инварианты:** «инкремент = полная сборка» (раздел 9); стабильность ключей и `body_hash` при переформатировании и смене CRLF/LF; повторная индексация без изменений не меняет `meta.generation`; инварианты таблиц из раздела 4.

Пока `Bench/README.md` нет, адаптер — единственное место, которое от него зависит: модули и экспорт от формата эталонов не зависят.

### 14. Отступления от принципов лида

1. **Раскладка проекта перед извлечением (принципы 3 и 5).** Ключ C# содержит сборку, а ключ объекта Unity — GUID; оба лежат не в самом файле (`.asmdef` выше по дереву, соседний `.meta`). Поэтому модуль — чистая функция не «файл → факты», а «(файл, `FileCtx`) → факты», а в конвейере появляется шаг раскладки; `ctx_hash` входит в ключ кэша. Чистота и параллельность сохраняются.
2. **Таблиц больше шести (принцип 7).** К «узлам, рёбрам, фактам-ссылкам, файлам, неразрешённым, FTS» добавлены `decls` (узел с несколькими местами объявления: `partial`, пространства имён, `#if` — иначе удаление одного файла ломает узел другого), `ref_deps` (без неё инкремент пропускает цепочки через тип получателя: правка возвращаемого типа `Foo.Create` должна перевязать `x.Bar()` в другом файле), `fact_cache` (кэш по хэшу из принципа 3 и области/импорты для повторного разрешения без разбора), `meta`. Все — общие, не по видам сущностей.
3. **Ребро на каждое место ссылки.** Принцип 4 требует доказательство «файл, строка, столбец»; одно ребро на `(src, dst, вид)` потеряло бы остальные места и усложнило бы инкремент. Поэтому ребро из ссылки 1:1 с `refs` (`ref_id UNIQUE`), схлопывание — в запросах и кэше смежности.
4. **Инкремент — по именам и по зависимостям (принцип 6).** Обратного индекса имён и импортов недостаточно (пример выше), добавлены `ref_deps` и `iface_hash` (правка только тела не трогает чужие ссылки). Исключение из «без полной пересборки»: смена `.asmdef`/`tsconfig`/`go.mod`/`Cargo.toml` или версии модуля — полное разрешение языка (редко; иначе видимость символов считать по частям слишком сложно).
5. **`contains` не хранится строками** — это `nodes.parent_id`; в словаре рёбер он есть, в `edges` — нет.
6. **Where-used Unity считается при запросе**, а не хранится: материализация «класс → все сцены» инвалидировалась бы при любой правке любого префаба в цепочке, а обход — миллисекунды по кэшу смежности.
7. **Не всё в YAML Unity — узлы:** Transform, встроенные компоненты и GameObject без скриптов — свойства, иначе крупные сцены дают сотни тысяч узлов без пользы для вопросов агента.
8. **Ключ C# не содержит путь файла** — в отличие от иллюстрации `путь#Класс.метод` в ADR-001 (раздел 5) и ADR-003: перенос скрипта в Unity не меняет GUID и не должен рвать память. Вход `target` по-прежнему принимает `путь#Класс.метод` (раздел 10.1), так что примеры ADR-003 работают.
9. **Добавлены источники `config` и `git`** к списку «treesitter/lsp/heuristic/model/unity-yaml» и `scip` из ADR-001 — иначе `co_change` (ADR-003) и связи из манифестов пришлось бы метить неверно.

## Отвергнутые варианты

- **Целочисленный id узла как внешний адрес** (ue-xray) — пересоздание строки уводит ссылки из рёбер, FTS и памяти агента; сервер ue-xray даже предупреждал, что «запомненные id могут указывать на другие строки». Внутренний rowid оставлен, но только за upsert по ключу и с `ON DELETE CASCADE`.
- **Рёбра по строковым ключам** (`edges(src_key, dst_key)`) — таблица в 4–5 раз больше и медленнее соединения; стабильность и так даёт upsert по ключу.
- **Ключ как символ SCIP дословно** (`scip-dotnet nuget Pkg 1.0 Ns/Type#M().`) — хуже читается агентом; дизамбигуатор перегрузок `(+1)` зависит от порядка объявлений. Совместимость с SCIP не нужна на уровне строк: `.scip` сопоставляется с нашими узлами по позициям определений.
- **Ключ `путь#Класс.метод` для всех языков** (Graft, иллюстрация ADR-001) — в C# и Unity перенос файла рвал бы привязки памяти, хотя Unity сохраняет GUID; для TS/JS так и сделано, потому что модуль там — файл.
- **Ключ без сборки или пакета** (только полное имя) — совпадения между `.asmdef`, одноимённые пакеты Go в разных модулях.
- **Хэш-идентификаторы узлов** — стабильны, но нечитаемы, и агент не может их угадать из имени.
- **Таблица на вид сущности** (ue-xray: 121 таблица) — каждый новый вид — правки в 5–7 местах; у нас вид — значение поля.
- **Разрешение в момент вставки** (ue-xray `insert_cpp_call`) — зависит от порядка файлов и не перевязывает ссылки при правке цели.
- **Полная пересборка рёбер на каждое обновление** (ue-xray `build_graph_edges`; у Graft полный проход разрешения) — не укладывается в бюджет хука; полная сборка оставлена как `index --full` и эталон теста.
- **Подбор цели по имени при неизвестном получателе** (CodeGraph, codegraph `name-matcher`) — ложные рёбра, которые нельзя отличить от настоящих (точность 73% → 37% по данным Graft).
- **`AMBIGUOUS`-рёбра от разбора в основном графе** — противоречит К3 ADR-001; неоднозначное — только кандидатами в `unresolved`.
- **Графовая БД** (Kuzu/LadybugDB, Neo4j) или **граф только в памяти** с сериализацией — нужны SQL, FTS, несколько процессов (хук и сервер) над одним индексом; лидеры рынка обходятся SQLite.
- **Materialized where-used Unity** — дорогая инвалидация по цепочкам префабов при каждой правке.
- **Узел на каждый YAML-документ** (Transform, рендереры) — раздувает базу без пользы для вопросов.
- **Общий извлекатель на `tags.scm` для C#, TS, Go, Rust** (Graft «широкий» уровень) — нет типа получателя и импортов; остаётся путём для других языков от сообщества ([[F-13 Публикация для сообщества]]).
- **Tantivy вместо FTS5** — лишняя зависимость и второе хранилище при достаточном BM25 FTS5 (К9, Д10).
- **Свежесть только через сторож файлов (`notify`)** — сторож не работает, когда сервер не запущен (хуки, CLI); основа — отпечаток и хуки, сторож — возможное ускорение в сервере.
- **Roslyn/LSP как основной путь для C#** — секунды и гигабайты на Unity-проекте, нужны `.csproj` (Д3); оставлены как уточнение по запросу (шаг 5 конвейера).
