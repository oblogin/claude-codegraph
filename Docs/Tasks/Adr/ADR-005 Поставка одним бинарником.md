# ADR-005 Поставка одним бинарником

> **Решение:** плагин поставляется как папка `plugin/` с одним Rust-бинарником `codegraph` в `plugin/bin/`, который обслуживает CLI, MCP и хуки; в прототипе бинарник собирается из исходников.
> **Почему:** один файл без Node, Python и Docker ставится одной командой и стартует за миллисекунды, что важно для хуков.
> **Следствия:** на машине разработки нужны Rust (rustup) и MSVC; для публикации понадобятся готовые сборки под три ОС.

## Контекст

Вопрос [[F03-02 Язык ядра и способ поставки]]. Язык выбран в [[ADR-004 Своё ядро на Rust]]; поставка локальной модели — в [[ADR-002 Локальные модели для простых задач]].

## Решение

- Rust 1.93+ (как ue-xray), целевая платформа прототипа — Windows x64 (MSVC).
- `codegraph index | query | mcp | hook <событие>`; `.mcp.json` плагина запускает `codegraph mcp`; `hooks/hooks.json` вызывает `codegraph hook …`.
- Грамматики tree-sitter вкомпилированы в бинарник; SQLite встроен (`rusqlite` с `bundled`).
- Локальная модель — только HTTP к Ollama или LM Studio; установка по клику — командой плагина через `winget`/`brew`.
- Прототип: `cargo build --release`, копирование бинарника в `plugin/bin/`, подключение плагина как локального маркетплейса (как `claude-tasks`).
- Публикация: сборки в CI под Windows, macOS, Linux ([[F-13 Публикация для сообщества]]).

## Отвергнутые варианты

- Хуки на Node или PowerShell — лишняя зависимость и медленный старт.
- Отдельные бинарники для MCP и хуков — две сборки, расхождение версий.
- Динамическая загрузка грамматик — сложнее установка; число языков небольшое.
